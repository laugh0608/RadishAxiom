# ADR 0032：AX-B01 的 P5 具体输入检查组件入口

日期：2026-11-07。状态：Accepted。项目所有者已接受本文的有限范围并要求实施。

本文为 AX-B01 具体数据检查定义独立的内部组件入口，供管线实施者和独立复核者查阅。生产管线与公共制品的验收沿用现有契约。

## 背景

[ADR 0007 的 P5](0007-first-verification-first-compilation-pipeline.md#p5具体输入与黄金制品检查)要求根据 IR 检查具体输入和黄金输出，再形成宿主数据。该阶段的纯数据检查无须执行 cvc5 或 Node。完整管线的实施条件仍适用。[ADR 0016](0016-core-semantic-slice-entry.md)已为 P1–P2 单独接受分阶段入口，本 ADR 为 P5 的数据检查接受同类的有限例外。

[现行制品契约](../../contracts/pipeline-artifacts-v0.1/README.md)绑定 IR v0.1，当前 P2–P4 的 AX-B01 材料使用 IR v0.2。迁移后的接口和本例的前置谓词语义保持一致，文档和契约 ID 随版本域变化。首批在当前 IR v0.2 路径上交付内部检查结果，公共封套与新 IR 的配对留给后续版本审阅。[原样本和两套身份的核对记录](../records/2026-11-07-ax-b01-p5-entry-review.md)

## 实施范围

1. 在现有 `axiom-ir` 中接收已严格检查的 `CanonicalDocument`（IR v0.2）、调用方选定的 benchmark 身份、原始 `axiom-benchmark-data` v0.1 字节及预期原始 SHA-256、所检查的输入或黄金输出角色和显式预算。按实际 IR 解析输入、输出接口和所有 `assume`。`benchmark_id` 用于核对调用方选择的任务，不参与选择字段、表达式或预期判定。
2. 首批支持 AX-B01 所需的输入 / 过滤 / 映射接口形状、Text 单主键、Int / Text / Enum 字段，以及输入 `forall_rows` 内对同行 Int 字段的 `le` 前置条件。值、字段、键和容量均取自 IR 声明。拒绝超出范围的形状或前置条件。检查 `invalid-input` 角色的数据时走正常输入检查，角色本身不给出结论。
3. 核对闭合 JSON、版本和角色、表名顺序、表 / 行结构、值域、枚举成员、键唯一性和容量。输入完成这些检查后求值每项 `assume`。黄金输出按对应输出类型核验，业务结果比对留给 P8。组件复用 P1 的数据模型和数学整数比较。
4. 成功返回绑定 IR v0.2 文档 ID 与原 fixture SHA-256 的内部结果，提供按表名和 IR 主键排序的类型化表值。失败分别保留结构 / 绑定错误、具体数据拒绝、功能未支持及资源耗尽。对前置不满足，定位实际契约、表、键和相关字段。数据失败或预算耗尽时停止产生成功结果。

## 验收与停止线

- 用原 `base` / `boundary` 输入和黄金输出逐项核对类型、行与顺序。测试中按现有 `tables` 布局投影，与独立算出的规范字节比较。用重新排列的输入行核对主键排序。完整旧封套字节作为 IR v0.1 兼容参考。
- 原 `invalid` 必须依据实际前置条件拒绝并定位 `orders:OX`。更换为仍在支持范围内、但使同一行成立的前置条件，确认结果随 IR 改变。再核对重复键、超容量、错误角色 / 摘要、重复 JSON 成员、未知字段或值、未支持前置条件及预算耗尽。区分具体拒绝和检查中断。
- 调用方明确原始输入字节、解析层级、表和行数、值单元、整数位数、求值工作量和输出的预算。若后续复用引发 P4 可观察差异、需扩大 IR 语义或需改公共配对，先提交差异供审阅。

接受范围限于纯组件及本机验收。P5 的生产 `check-fixture` execution、`axiom-host-data` 公共配对、Evidence 与 receipt 装配，以及 P6 生成门控继续受各自契约约束。真实工具、宿主运行、依赖安装和跨仓变更按各自授权办理。
