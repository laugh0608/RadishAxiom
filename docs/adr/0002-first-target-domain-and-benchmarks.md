# ADR 0002：首个目标领域与基准任务

日期：2026-08-20

状态：Accepted

用途：冻结 RadishAxiom 首个目标领域、最小纵向闭环和首批基准任务，作为后续语义、Axiom IR、Axiom Evidence 与工具链设计的共同约束。

读者：语言与验证设计者、实现者、评测维护者和审阅首版范围的项目维护者。

不包含：表面语法、编译器实现语言、验证后端、Axiom IR 编码、Axiom Evidence 序列化、宿主运行时选择或实现计划。

## 背景

RadishAxiom 需要先在一个边界清楚的窄领域内证明“约束显式、失败可反例化、信任可见、Evidence 可复核”能够形成真实闭环。若首域依赖网络、文件系统、时间或生产数据，语言语义、环境行为和外部系统故障会同时进入结果，难以判断 Agent 失败究竟来自表示、约束、验证器还是世界状态。

研究备忘支持“受约束表示可能改善窄域 Agent 任务”的有限假设，但没有证明任何具体 DSL、语法或验证后端天然更优。因此，本决策选择能够隔离这些变量、又具有真实 Agent 价值的领域，并把可反驳的任务契约置于技术选型之前。

| 候选领域 | Agent 实际价值 | 输入 / 副作用边界 | 可验证性 | 反例质量 | 可信边界 | 现有运行时承载能力 | 实现成本 |
| --- | --- | --- | --- | --- | --- | --- | --- |

选择“有键有限表的确定性转换”。它不是因为表格 DSL 已被证明优于成熟语言，而是因为它能以最低的外部噪声同时检验 RadishAxiom 的核心主张：规范化表示、显式中间状态、类型与效果、验证义务、最小反例、信任清单和可复核 Evidence。

有限资源排程保留为后续相邻领域候选；它有优质反例，但会过早引入搜索和最优性。文件系统计划与外部 API 工作流延后到纯计划语义和 Evidence 边界稳定之后，不能用模拟成功替代真实副作用正确性。

## 决策

### 目标领域

首个目标领域是**有键有限表的确定性转换**：程序接收一组已经物化、具有显式模式和键约束的有限输入表，产生一组有限输出表。转换核心必须是确定且无外部副作用的；输入获取和输出持久化位于核心之外，并进入 Evidence 的效果与信任清单。

首批任务只要求足以表达以下语义的最小集合：

- 值类型：布尔、受界整数、定标整数表示的定点数、文本、闭合枚举、可选值和记录；不使用二进制浮点；
- 表：有限、无语义行序、具有显式主键；重复键、缺失必填值和越界数值是输入不符合，而不是静默修复条件；
- 转换：筛选、投影、字段重命名、总函数派生、基于已声明键的等值连接，以及按键分组的 `count` / `sum`；
- 约束：模式一致性、键唯一性、外键、连接基数、行覆盖、算术范围、聚合守恒和字段非干扰；
- 结果比较：按声明键规范化排序后比较；排序只服务重放与差异展示，不进入表的领域语义。

这里冻结的是领域能力和可观察语义，不是语法节点、IR 指令、验证算法或运行时 API。后续设计可以缩小操作集合，但若删除后无法完成本 ADR 的四个基准任务，则必须替代本 ADR。

### 最小纵向闭环

首版实现必须让一个任务从约束到 Evidence 完整通过以下链路，不能用手写结果或只跑黄金样例代替其中任一步：

1. 接收版本化的任务契约、有限合成输入和候选转换；记录原始制品摘要，输入解码位于显式信任边界。
2. 将候选转换规范化为唯一 Axiom IR 语义表示；人类投影与机器序列化不得形成两套语义。
3. 检查值、记录、表、键和效果；转换核心的效果集合必须为空，外部读写由评测驱动单独记录。
4. 为任务契约生成可追踪的验证义务，至少覆盖总定义性、键与基数、范围、覆盖 / 守恒或非干扰中与任务相关的部分。
5. 对每项义务给出 `proved`、`checked`、`unknown`、`failed` 或 `trusted`，并保留规则、假设和工具版本；`unknown` 不得降级为成功，`trusted` 不得替代核心语义义务。
6. 对 `failed` 产生能够重放的最小行、键、字段、数值或成对输入反例；无法证明最小时必须准确标为“已缩减见证”。
7. 仅在必需义务没有 `failed` 或 `unknown` 后，在一个尚待选择的现有宿主运行时执行纯转换；规范化实际输出并与黄金结果比较，动态结果只能记为 `checked`。
8. 输出 Axiom Evidence，并由独立于生产报告路径的最小检查入口复核制品摘要、义务关联、状态使用、反例重放和信任清单。证书级别与后端仍由后续决策确定。

### 基准共通协议

四个任务使用合成数据，不访问网络、文件系统、时钟、随机源、环境变量或生产凭据。本文中的示例夹具和黄金结果固定任务含义；边界夹具、无效输入、错误候选和 Expected Evidence 断言已经物化为[有键有限表基准语料库 v0.1](../benchmarks/keyed-finite-table-corpus-v0.md)。

基准通过规则如下：

- 对所有满足输入前置条件的值都成立的核心语义义务必须为 `proved`；只在任务明确封闭的有限夹具上比较输入或输出时可为 `checked`；
- `trusted` 只记录规范真实性、输入来源、宿主执行等不可由核心证明的边界，不能解除必需义务；
- 任一必需义务为 `unknown` 或 `failed`，任务即不通过；错误候选则必须被拒绝并产生规定类别的反例；
- 分别记录解析、类型 / 效果、契约、实际输出和 Evidence 复核结果，不合并成一个缺少来源的“成功”；
- Agent 实验必须固定模型与版本、上下文预算、零样例 / 少样例 / 验证反馈条件、提示摘要、工具权限、重试策略、语料库版本和工具链版本；三种表示至少包括领域常用语言、普通结构化 schema / DSL 和候选 Axiom 投影；
- 在查看完整结果前冻结成功阈值与停止条件，并分别统计隐藏任务通过率、修正轮数、token / 时间、验证时间、反例是否有效及跨模型稳定性。

本文不把任何当前模型成绩写成产品门槛。基准首先用于比较表示和反馈闭环；只有可复现实验才能支持后续泛化结论。

## 基准任务

### AX-B01：结算订单净额

示例输入 `orders`：

| `order_id`（主键） | `state` | `subtotal_cents` | `discount_cents` |
| --- | --- | ---: | ---: |
| `O1` | `settled` | 1000 | 100 |
| `O2` | `pending` | 500 | 0 |
| `O3` | `settled` | 750 | 750 |

黄金输出：`(O1, 900)`、`(O3, 0)`，输出键为 `order_id`。

- **约束**：金额为受界非负整数，`discount_cents <= subtotal_cents`；输出包含且只包含 `settled` 订单；`net_cents = subtotal_cents - discount_cents`；计算不得溢出；除 `order_id` 与 `net_cents` 外不输出其他字段；核心无效果。
- **成功条件**：对全部有效输入证明筛选完备性、筛选可靠性、公式与范围，示例及边界夹具的规范化输出与黄金结果一致。
- **失败反例**：对把减法写成加法的候选，`O1` 是具体见证（期望 900，得到 1100）；对错误排除零净额的候选，`O3` 是行覆盖见证。反例必须标出失败约束和派生路径。
- **信任假设**：任务规范正确表达“净额”；输入解码忠实；宿主运行时忠实执行受界整数语义。真实订单状态是否准确不在证明范围内。
- **预期 Evidence**：输入模式与夹具摘要、纯效果检查、筛选双向义务、算术等式与无溢出义务、黄金输出检查、规则 / 工具版本和信任清单；错误候选产生 `failed` 及单行反例。

### AX-B02：客户等级连接

示例输入：

| `orders.order_id`（主键） | `customer_id`（外键） | `region` |
| --- | --- | --- |
| `O1` | `C1` | `north` |
| `O2` | `C2` | `north` |

| `customers.customer_id`（主键） | `tier` | `region` |
| --- | --- | --- |
| `C1` | `gold` | `north` |
| `C2` | `silver` | `north` |

黄金输出：`(O1, gold)`、`(O2, silver)`，输出键为 `order_id`。

- **约束**：两个主键分别唯一；每个 `orders.customer_id` 必须引用恰好一个客户；输出对每个订单恰好一行，不得丢行或扇出；`tier` 必须来自所引用客户；核心无效果。
- **成功条件**：对全部满足键与外键前置条件的输入证明一对一输出覆盖和字段来源，示例与边界夹具输出一致。
- **失败反例**：按 `region` 而非 `customer_id` 连接的候选会让 `O1` 同时匹配 `C1`、`C2`；最小见证包含一笔订单和两个同区客户，并标出违反“恰好一行”的连接路径。
- **信任假设**：输入声明的键、外键和字段含义正确；运行前对具体夹具的键约束进行了检查；宿主的文本 / 枚举相等性符合领域语义。
- **预期 Evidence**：两表模式与摘要、键和外键检查、连接条件、输出存在性 / 唯一性义务、`tier` 字段沿袭关系、黄金输出检查与信任清单；错误候选产生扇出反例而不是只报告行数不同。

### AX-B03：账户用量汇总

示例输入 `usage_events`：

| `event_id`（主键） | `account_id` | `units` |
| --- | --- | ---: |
| `E1` | `A1` | 4 |
| `E2` | `A1` | 6 |
| `E3` | `A2` | 3 |

黄金输出：`(A1, 2, 10)`、`(A2, 1, 3)`，字段依次为 `account_id`、`event_count`、`total_units`，输出键为 `account_id`。

- **约束**：`event_id` 唯一，`units` 为受界非负整数；每个输入事件恰好进入与其 `account_id` 相同的一个分组；组内 `event_count` 和 `total_units` 分别等于计数与求和；全局计数和总量在输入、输出之间守恒；聚合不得溢出；核心无效果。
- **成功条件**：证明分组覆盖、不相交、组内定义、两项全局守恒和范围安全；示例、空表、单组和边界数值夹具输出一致。
- **失败反例**：把所有事件汇总为单组的候选由 `E1` 与 `E3` 构成跨账户见证；先重复再聚合的候选必须给出导致计数或总量不守恒的事件键和路径。
- **信任假设**：`account_id` 表示预期账户边界；输入单位已经统一且无隐含换算；宿主聚合忠实实现规定的受界加法。
- **预期 Evidence**：输入键与范围检查、分组分区义务、组内计数 / 求和定义、全局守恒、无溢出、黄金输出检查和信任清单；错误候选产生包含相关事件键的缩减见证。

### AX-B04：工单最小化导出

示例输入 `tickets`：

| `ticket_id`（主键） | `category` | `priority` | `contact_email`（敏感） | `internal_note`（敏感） |
| --- | --- | --- | --- | --- |
| `T1` | `billing` | `high` | `a@example.test` | `manual review` |
| `T2` | `support` | `low` | `b@example.test` | `known issue` |

黄金输出：`(T1, billing, high)`、`(T2, support, low)`，输出键为 `ticket_id`。

- **约束**：输出恰好保留全部输入行，只含 `ticket_id`、`category`、`priority`；输出值、行存在性和输出键均不得依赖 `contact_email` 或 `internal_note`；首版不允许解密、哈希、脱敏替换或显式降密；核心无效果。
- **成功条件**：证明字段白名单、行覆盖以及相对于两个敏感字段的非干扰；示例和只改变敏感字段的成对夹具产生相同输出。
- **失败反例**：若候选按 `contact_email == a@example.test` 筛选，则两份仅把 `T1.contact_email` 从 `a@example.test` 改为 `z@example.test` 的单行输入形成成对见证，输出分别存在和缺失；直接输出敏感字段时应给出字段依赖路径。
- **信任假设**：字段敏感级别由任务所有者正确标注；未标注字段不会被系统猜测为敏感；输入解码和宿主字段访问忠实。此证明不声称导出满足任何现实法规。
- **预期 Evidence**：字段分类及其来源、输出白名单、行覆盖、字段依赖 / 非干扰义务、成对夹具检查、黄金输出检查和信任清单；错误候选产生字段路径或成对输入反例。

## 首版明确不包含

- 在转换核心内读取或写入文件、数据库、网络、环境变量、时钟、随机源或共享状态；
- 流式、无限、增量或分布式表，以及并发和事务语义；
- 任意递归、循环、用户自定义外部函数、插件、反射、宏或元编程；
- 二进制浮点、近似聚合、汇率 / 单位自动换算、无界数值或隐式数值截断；
- 外连接、交叉连接、任意谓词连接、窗口函数、依赖行顺序的语义或通用 SQL 兼容；
- 查询优化器、索引、并行执行、成本模型、生产规模性能或数据库替代目标；
- 敏感数据自动识别、降密、加密、匿名化保证或法规合规声明；
- 从示例推断真实业务意图，或把黄金输出、动态测试和模拟执行表述为形式证明；
- 冻结表面语法、实现语言、验证后端、运行时、公共 IR 编码或 Evidence 证书格式。

## 进入实现阶段的验收条件

只有同时满足以下条件，项目才可从设计进入编译器 / 检查器实现；实验性文档原型不等于满足条件：

1. 本 ADR 与产品定义、当前状态完成一致性审阅，四个任务的领域边界无相互矛盾。
2. 单独的类型化语义规范定义值、表、键、空值、算术、连接、聚合、非干扰、错误和效果，且能逐项映射四个任务的义务。
3. Axiom IR 设计给出规范化、版本、确定性序列化或等价稳定标识、人类无损投影和语义差异规则，但不依赖表面语法。
4. Axiom Evidence 设计定义五种状态的使用规则、义务追踪、假设与信任清单、反例表示、工具版本和独立检查边界。
5. [四个任务的版本化语料库](../benchmarks/keyed-finite-table-corpus-v0.md)已物化，包含公开示例、边界夹具、无效输入、正确参考转换、至少两个错误候选、黄金输出和预期 Evidence 断言；生成或整理过程可重放且摘要固定。
6. 实现语言、验证后端和至少一个现有宿主运行时完成基于上述任务的比较，明确可信计算基、`unknown` 行为、许可证、维护成本和替代方案，再分别通过后续决策冻结。
7. 在运行 Agent 对比实验前预注册表示变体、模型 / 上下文条件、指标、成功阈值和停止条件；不得根据完整结果反向调整门槛。
8. 评审确认最小闭环无需网络、生产数据或兄弟项目即可独立复现，且没有以 `trusted` 或动态样例绕过核心义务。

## 后果

收益：

- 首个实现可以把环境噪声与语言 / 验证问题分离，失败能够稳定缩减到数据级反例；
- 四个任务覆盖行级算术、跨表基数、跨行守恒和敏感字段非干扰，不会把“会做筛选”误当成验证优先闭环；
- 任何常见宿主运行时都可能承载候选执行，技术栈比较可以晚于语义与 Evidence；
- 基准可以直接检验规范形式、显式状态、验证反馈和 Evidence 复核等研究假设。

代价与风险：

- 结论只适用于有限纯转换，不能外推到外部工具调用或通用程序；
- 输入模式、业务约束和敏感字段标注仍可能错误，证明不会自动修复错误规范；
- 连接、聚合与非干扰使首版高于玩具表达式验证的成本，但它们是区分真实闭环与演示路径的最低代表性集合；
- 生产数据规模、运行时性能和外部副作用被有意推迟，后续扩域必须重新评估可信边界。

## 变更要求

若修改首个目标领域、删除使任一 AX-B01 至 AX-B04 无法表达的能力、放宽纯效果边界、改变基准通过规则或允许 `trusted` 解除核心义务，必须以新的 ADR 替代本决策，并同步产品定义和当前状态。仅调整表面语法、实现语言、验证后端、宿主运行时或序列化格式，不自动构成本 ADR 的替代，但必须保持这里的语义与证据边界。
