# Axiom IR v0.1 → v0.2 显式迁移

日期：2026-10-05

状态：Normative（规则 `axiom-ir-0.1-to-0.2`，版本 `1`）

用途：为本仓内部 P1 组件定义可验证的单向迁移与失败边界。不定义产品 CLI、通用迁移框架、新 Evidence 格式、运行凭证或自动升级策略。

## 精确两端

| 项目 | 源 | 目标 |
| --- | --- | --- |
| IR 版本 | `0.1` | `0.2` |
| 语义 | [旧快照](../semantics/keyed-finite-table-semantics.md) | [v0.2 快照](../semantics/keyed-finite-table-semantics-v0.2.md) |
| 语义 SHA-256 | `6b18d65eefa439956db8eebe1f4ce90e08b4def4abf7c718c2605e7528598d0d` | `a40ec7c4eecfde23a340fb61b67727b5393f01b7288d151a34168ec88a87dac7` |
| 内容身份域 | `axiom-ir-v0.1:*` | `axiom-ir-v0.2:*` |

源必须是严格规范机器字节。pretty 或其他可规范化表示须先经源版本 normalizer，由调用方显式决定使用其输出；迁移器不能静默改写源输入再记录另一份源身份。未知版本、错配摘要、重复或悬空引用、未知成员、坏类型、Unsupported 与资源失败全部原样拒绝，不产生目标或成功记录。

## 规则与处理顺序

1. 完成源版本全部现有结构、类型、图、契约、内容身份与 strict 字节检查，确认版本为 `0.1`，计算源文档域 ID。源版未定义 record / is_some 载荷、记录 eq / join 或复杂键投影不能靠目标规则补全。
2. 枚举内容保持不变，在目标 enum-type 域重算 ID。
3. 依赖先于引用者处理记录声明，重绑类型中的 enum / record 引用，按目标域重算记录 ID；然后重绑表的 record_type 并重算表 ID。递归记录依旧拒绝，不沿任意深度引用使用递归调用栈。
4. 按源 DAG 拓扑顺序处理节点：重绑 table_type、源节点 / left / right 引用，以及嵌入表达式中的 enum / record 类型引用；重新执行目标表达式与节点规范化，然后重算节点 ID。ID 改变可能改变 eq / and / or 的 JCS 顺序，不能沿用旧操作数顺序计算目标摘要。
5. 重绑契约表达式中的类型引用，重新规范化并重算契约 ID；接口引用仍按原类别和名称绑定，量词、Option、查找键、角色、结果范围与非干扰集合均不改义。
6. 重绑 outputs.node，替换顶层版本和语义绑定，按目标 ID / 名称重排无语义顺序数组，生成目标机器字节并用目标文档域计算 ID。
7. 再经真实 v0.2 normalizer 和 strict 入口检查目标；任何失败都不返回成功迁移。不得去重冲突 ID、删节点、改字段标签、折叠常量或修改任务约束以求通过。

只重写上述结构化引用位置。名称、枚举成员、Text 字面值、字段名、接口名即使恰好与某个 ID 同拼写也必须原样保留。不做全局字符串替换，也不推断未定义字段的语义。

## 返回与留存

内部迁移 API 返回只读目标文档与迁移记录。记录包含工具名称与 crate 版本、规则名称与版本、源 / 目标 IR 版本、语义摘要、文档域 ID，以及五类 definition 的源 → 目标 ID 对照。映射按类别和源 ID 排序；没有丢失语义列表的“默认成功”，当前规则只能返回上述无损共同子集或失败。

该类型化记录不是新公共 Evidence / pipeline receipt，也不是产品工具身份或来源认证。当前工具名称为 `radishaxiom-ir`，crate 版本为 `0.0.0`，规则版本为 `1`；持久归档者还须记录实际工具构建 / 仓库修订与源字节，以重现具体实现。仓库兼容 fixture 清单记录两端精确字节、文件摘要、文档身份与独立生成入口。

输入和目标共用调用方明确给出的 JSON 字节 / 值数 / 嵌套限制；每次解析都执行相同限制，不因去重后的目标较小而绕过原始源限制。当前规则保持文档字段和引用长度；规范数组重排不增加目标字节量。组件会同时保留源分析、映射、目标树和字节，不承诺 OS 硬内存配额。

不接受 v0.2 作为源，不提供幂等“已迁移”成功或反向降级；调用方必须明确选择规则。迁移对 wrong 候选只说明格式、结构与身份可保留，不判断算法正确、不转移 `proved` / `checked` / `trusted`，也不授予执行能力。

## 下游交接

新 IR 身份不能用于旧 Evidence 或旧 pipeline / runtime 绑定。目标 Evidence profile 尚未接受，须沿 ADR 0009 审阅；独立 checker 导入目标规范及精确 fixture 后还须由独立实现重算并验证拒绝材料。本仓 Python 独立期望可对照迁移算法，但不代替真实 checker、证明或跨平台运行。

旧规范、12 个候选、fixture、28 个 bundle 和实验注册原字节保留。目标候选与构造正负例位于[兼容材料](../../crates/axiom-ir/tests/fixtures/v0.2/README.md)，生成器不得用 expected outcome 决定迁移、类型或成功状态。
