# P1 支持边界与验收矩阵审阅

审阅日期：2026-10-05

用途：保存 P1 初次支持边界审阅，并核对接受后的实际矩阵。本文不替代正式规范；初次提出的四项范围现已由 [ADR 0017](../adr/0017-ir-v0.2-support-boundaries-and-migration.md)接受，规范与迁移细则以该 ADR 链接的版本化文件为准。当前顺位由[当前状态](../status/current.md)维护，实际接口见 [IR 组件](../../crates/axiom-ir/README.md)。

## 初次审阅：可按 v0.1 规范完成的部分

[首域语义的相等、顺序与转换](../semantics/keyed-finite-table-semantics.md#相等顺序与转换)对 Int 使用数学数值顺序；完全同型要求分别用于相等和 Int 加减。[IR 标量操作](axiom-ir-v0.md#标量操作)把 `lt` / `le` / `gt` / `ge` 交由该数值语义约束，没有附加上下界相同条件。因此不同范围 Int 的有序比较可直接实现，无需新 tag、数字转换或范围合并。

本轮移除内部 `MixedIntComparison` 未支持分支；六种范围的全部有序对经四种比较检查，保留左右顺序、各自类型和完整十进制值。Int 与 Fixed、Bool、Option 混比仍拒绝；不同范围 Int 的 `eq` / 加法仍按完全同型要求拒绝。独立完整文档向量覆盖节点谓词、契约、敏感控制标签、规范字节和内容身份。类型通过不判断比较真值、契约可满足性或范围义务。

另一处实现缺陷是 `lookup_join.pairs` 原先只检查同型，能接受记录或可选记录字段，绕过逐行 `eq` 的记录相等未支持边界。本轮先以失败回归复现，再让二者共用相等支持集合。连接现在返回带原字段对路径的 `UnsupportedRecordComparison`，并传递到节点、契约、完整文档及 strict 入口；标量及其 Option 包装仍可通过。本项修复成功误报，不宣称已经裁定记录比较的最终规范非法类别。

## 初次审阅：当时待决定的规范问题

| 项目 | 原文与缺口 | 当前实现 | 建议的新版本边界 |
| --- | --- | --- | --- |
| `record.fields` | [字面值与构造](axiom-ir-v0.md#字面值与构造)指定 `record_type` 与按名称排序、恰好覆盖的 `fields`，但未定义数组元素的精确成员；本仓无该构造的既有机器样例 | `UnspecifiedForm` | 每项闭合为 `name` / `expression`，与节点投影用同一拼写；按 Unicode scalar 名称排序、唯一、完整且逐字段完全同型；不得添加缓存类型 / 标签 |
| `is_some` | [表类型](axiom-ir-v0.md#表类型)的外键说明引用该名字，闭合表达式表却没有其成员或绑定规则 | `UnspecifiedForm`；已有 `lookup` 与 `match_option` 可表达存在性 | 将它明确为说明中的简写；规范机器形式使用已有 `match_option`，不新增第二个核心操作 |
| 记录相等 | 语义不提供记录的通用隐式相等；IR `eq` 表只写同型，连接字段对也只写同型，未闭合这些规则之间的适用范围 | 直接记录和任意 Option 包装在表达式 / 连接两路均为 Unsupported | 明确通用 `eq` 与连接字段对的集合为标量及递归 Option；排除 Record / Option<Record>，需要记录比较时按字段显式构造公式 |
| 复杂主键投影 | [投影、重命名与派生](../semantics/keyed-finite-table-semantics.md#投影重命名与派生)要求逐字段保留 / 一一重命名且值不变，禁止任意表达式生成新键；没有定义“语法上直接读取”与“可证明同值”的判定界线 | 直接源键读取可通过；如 `if p then key else key` 返回 `UnsupportedKeyExpression` | 明确 map / join 输出键必须直接读取对应源行 / 左行键字段并形成双射；复杂表达式即使数学等价也不作为首版键投影，无新增求解或单射性义务 |

推荐的记录构造字段形式如下；这是待接受的模板，`<record-type-id>` 为说明占位，不能直接作为机器输入：

```json
{
  "op": "record",
  "record_type": "sha256:<record-type-id>",
  "fields": [{ "name": "enabled", "expression": { "op": "literal_bool", "value": true } }]
}
```

存在性简写 `is_some(e)` 对应以下现有结构：`match_option` 的 `subject = e`、`none = literal_bool(false)`、`some = literal_bool(true)`、`result_type = bool`。内部值仍按现有规则绑定于 some 分支索引 0；该分支常量不使用它。`e` 只出现一次，不加入隐式解包、求值折叠或新的 canonical 重写。

## 推荐决策范围与兼容影响

以下保留接受前的提案与影响判断；接受事实见后节。建议按上述四项形成 **IR v0.2 的窄范围规范与迁移方案**，而不把未定义机器成员或拒绝集合静默补进 `0.1`。[现行版本策略](axiom-ir-v0.md#版本与兼容策略)要求成员、语义或拒绝行为变化至少提升 v0 minor；[ADR 0016](../adr/0016-core-semantic-slice-entry.md#停止条件后果与回退)要求出现规范歧义时只停相应部分。

待确认的范围是上述四项及其必要版本、摘要、兼容性材料，不包括其他语言扩展。实施方案必须满足：

1. 保留 v0.1 语义、IR、Evidence、候选及绑定字节；新规范另存并明确版本关系，不直接替换历史摘要。
2. 精确声明读取版本集合；旧读取器继续拒绝 `0.2`。若目标使用 `axiom-ir-v0.2:*` 域，则类型、节点、契约及文档 ID 都须重新计算，引用随迁移更新；不能只改顶层版本。新的语义原文字节也产生新的绑定摘要。
3. 显式迁移仅接受源版本实际能够验证的输入，记录具名规则、源 / 目标身份并重新验证。对旧版仍未定义的 record / is_some 载荷不能猜字段或填默认值；复杂键、记录相等若不能无损映射，须拒绝并定位。
4. 保留四题 12 个 v0.1 候选，另外建立目标版本正例、负例、同域输入与迁移对照。新增构造必须覆盖字段缺失 / 重复 / 错型、嵌套绑定、规范身份及标签依赖，不能只更新 schema 或成功样例。
5. 按 [IR 变更要求](axiom-ir-v0.md#变更要求)逐项审阅语义、Evidence、语料、独立 checker 与兼容性影响。旧 Evidence 不能绑定新 IR 身份；P2 的义务 profile 仍按 ADR 0009 单独闭合，不因本审阅自动接受 Evidence v0.2 或启动 P2。

本轮仅在 RadishAxiom 内形成提案，未修改兄弟仓库、运行真实 checker 或作远程写入。后续跨仓实现 / 外部执行仍须说明精确范围；不把尚未具备的独立复核写成已通过。

若暂不接受新版本范围，现有 v0.1 组件仍可处理其支持子集，但上述 Unsupported 不能靠改名、吞错或限定几个基准就算作完整 P1。也可提出另一组精确形式；届时应重新审阅可接受文档集合及迁移代价。

## 接受与实施结果

2026-10-05，项目所有者明确回复“接受，继续推进下一步”。[ADR 0017](../adr/0017-ir-v0.2-support-boundaries-and-migration.md)据此接受四项边界、IR v0.2 新规范 / 语义快照及显式迁移。本仓已实现两个精确版本的读取、记录构造、版本化拒绝与[迁移规则 1](ir-v0.1-to-v0.2-migration.md)；旧规范、Evidence、候选和绑定材料未改。v0.1 的原 Unsupported 保留，v0.2 按规范明确拒绝 is_some、记录 eq / join 和复杂键。

新增[兼容材料](../../crates/axiom-ir/tests/fixtures/v0.2/README.md)提供 20 份迁移对照、逐项身份映射和 18 份独立生成负例。语义负例重算修改项身份，实际拒绝须命中原路径的类型 / 结构原因。迁移重算六类域，重排因引用改变而排序变化的表达式；相同拼写的文本和名称保持不变。5,000 层记录 / 节点引用回归验证迁移不沿图递归。

## 验证与失败处理

新增五项测试：不同范围 Int 表达式、跨节点 / 契约文档、记录连接拒绝、标量 / Option 连接保留、Unicode 文档身份对照；已有版本负例补齐 `1.0`。完整文档独立向量由六个增至九个。

不同范围 Int 回归在修复前得到 `MixedIntComparison`，记录连接回归在修复前错误成功，精准测试均以退出码 101 复现，修复后通过。Unicode 对照首次断言使用全局名称替换，误改了记录声明中同名字段；限定为 outputs 成员后通过，未调整生产 Unicode 规则或独立期望。失败分别属于已确认实现缺口和测试输入变换错误，不作为不稳定测试忽略。最终 workspace / 仓库检查结果见[当前状态](../status/current.md#验证入口与本次审阅)。

v0.2 实施新增 12 项回归。首次编译暴露标签分析中局部变量遮蔽 helper，以及测试误将 label_gaps 作为图方法；均修正为正确调用后重跑通过，没有放宽规则或修改独立期望。完整 workspace、仓库一致性及未运行项目统一见当前状态。
