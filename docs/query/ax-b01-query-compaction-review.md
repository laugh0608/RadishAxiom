# AX-B01 紧凑查询表示方案与可行性审阅

日期：2026-10-17。状态：本地研究方案与有限可行性验收完成。本文保留研究阶段的选择与接入门槛；后续生产范围由 [ADR 0027](../adr/0027-compact-query-and-p4-binding.md) 接受，实际 Rust 实现与本机验收见[生产验收记录](../records/2026-10-17-compact-query-production-validation.md)。

用途：给项目所有者和实现者审阅查询表示的选择、等价性依据、模型布局约束及进入生产实现的门槛。

不包含：真实 solver、正式等价性证明、运行时间 / 峰值内存保证、完整 Evidence、跨仓 checker 或新资源授权。实际测量与命令另见[本批验收记录](../records/2026-10-17-query-compaction-validation.md)。

## 本次决定

选择类型化恒等化简、共享、可达裁剪、保序短名称与有界代入，作为下一份显式 query profile 的候选方案。原容量 72 条记录均实际降至 1 MiB 内，范围 265,107–962,850 字节；既有材料的 12,553 次有限比较及 324 次原容量观察通过。下一项是接受确定性的生产规则与 P4-A 接入范围后，在 Rust DAG 内实现并验收。当前不改变 `QueryProfile`、adapter 或生产请求行为。

## 问题与选择

[原尺寸审阅](ax-b01-query-size-review.md)已测量原容量三候选 / 四 profile 的 72 条记录（27 份不同 SMT 字节）：42,577,698–65,831,615 字节，全部超过 1,048,576 字节 stdin 上限。旧审阅中的短名称、可达裁剪与完全相同项共享只是尺寸估算，不能当作新表示已经可用。

本次先研究**同一有类型公式的紧凑表示**。保留现有 QF_UFLIA、全部自由输入、目标公式和 map / filter 支持集合；不改 lookup、键唯一性或双向覆盖关系，不引入数组、量词、排序假设或 AX-B01 特判。若这条路径足够解决字节阻断，就无需在本切片增加关系编码的语义审阅面。

| 方案 | 判断依据与处理 |
| --- | --- |
| 同一公式的恒等化简、共享、可达裁剪和有界代入 | 本次实际生成并独立有限核对；是优先研究方向 |
| 新的 lookup / 唯一键 / 覆盖关系编码 | 可能改变公式结构及模型解释的论证面；本次不实施，只有表示路径仍阻断才另立范围 |
| 扩大 stdin / 内存 / deadline | 缺少真实执行数据；本次保持原值，不由尺寸优化授权 |
| 缩容量或去掉义务 | 改变声明域与验收目标；不作为解除原容量阻断的方案 |

## 研究入口与生产入口的区别

[导出器](../../crates/axiom-ir/examples/export_query_compaction_inputs.rs)只调用既有 P1 / P2 / P3，导出原 SMT、原目标、完整符号及 origin。它保留三候选容量 100 和四版 profile 字节，不生成请求或五态。生成器摘要使用明确标为合成的诊断身份。

[研究原型](../../scripts/query_compaction_prototype.py)接收这些原字节，严格检查受限的有类型、拓扑有序公式，再生成单独的研究 SMT 和名称映射。产物不能传入既有 P4-A 并冒用原 `EncodedQuery`、profile、摘要或请求；原 P4-A 仍按旧字节拒绝原容量请求。

**未来生产实现应在 Rust 的有类型 DAG 内完成这些变换。** 不把 Python 研究 parser 接到生产管线，也不把“先生成几十 MB 的旧文本再压缩”作为最终路径。第一切片可保留现有完整 DAG 的生成顺序，在新 profile 的渲染分支规范化与裁剪；这保留旧版本，也避免提前引入另一套按需语义编码器。

## 变换规则与等价性依据

所有规则作用于已经类型检查的 SMT 全定义运算。IR 中的 fault、Ready、WF、Pre 与求值可达性已经由原编码显式表示为公式；不使用这些条件作为额外假设，也不把 IR 严格求值改成短路求值。

| 规则 | 适用条件 |
| --- | --- |
| `not` 常量、双重否定 | Bool；保留所表达的真值 |
| `and` / `or` 的单位元、吸收元、重复项消除 | 全部参数为 Bool；保留首次出现的不同项顺序，不假定输入或程序有效 |
| 相等自反、常量相等、相等两边按项编号排序 | 两边 sort 完全相同；自由 Text 不因 literal 名称而假定不同 |
| 加减常量、加零 / 减零、`x - x` | 数学整数；不是固定宽度宿主整数，不引入新范围假设 |
| 整数比较的相同项 / 常量 | 按 `<`、`<=`、`>`、`>=` 的精确边界 |
| `ite` 常量条件、相同分支、Bool 真 / 假分支 | 条件为 Bool，两分支同 sort；原公式的其他故障条件保持为原公式的一部分 |
| 相同项共享 | sort、运算、常量与有序前提一致；不同自由符号永不合并 |
| 可达裁剪 | 只删除断言根不可达的派生项；所有自由声明仍保留 |
| 短名称和有界代入 | 类型一致、名称双射、无变量捕获；没有新增自由变量或函数参数 |

论证按原拓扑序进行：常量值不变；每个自由符号经双射对应相同 sort 的同一输入；若前提取值相同，上表恒等规则与相同运算使当前项取值相同。删除未引用的零参数定义不改变断言；把无绑定变量的定义体代入引用不改变其值。此论证不依赖 WF 成立，因此也覆盖 WF / Pre 失败的赋值。

这是一份可审阅的数学论证和有限动态检查，**没有生成或独立检查等价性证明证书**。它也不弥补原编码未支持的图操作或义务。

## 确定性、模型布局与绑定

1. 输入声明与定义必须拓扑有序，引用只能指向较早的项；检查完整输入，包括最终被裁剪的无效定义。
2. 规范化按原定义顺序处理，完全相同项取首次代表。根可达项按代表编号排序输出，不依赖 hash 容器遍历顺序。
3. 自由符号按原完整名称字典序排序，再分配统一宽度的十进制 `s…` 名称，宽度取 `max(1, digits(max(0, N-1)))`。名称顺序必须严格保序；派生定义按实际输出序采用 `d0`、`d1` 等另一命名空间。AX-B01 的 501 个自由符号对应 `s000`–`s500`。
4. 外部映射完整保留 `old / new / sort / origin`。所有活动位、inactive 叶、Option 内部叶和 Text literal 都在映射中；不根据断言可达性删自由声明。
5. 原 P4-A 的未锚定 Text 类按最小自由名称排序。保序重命名使类排序保持，不产生新的 Text 值语义。相同模型赋值的名称往返、origin 到槽位的恢复仍须逐项核对。
6. 输入 port、类型、容量、主键和 component 索引取原 IR 与完整符号来源，不按 `orders`、字段名或候选名猜测。AX-B01 名称只选择诊断材料，不进入变换逻辑。

未来新 profile 必须绑定新规范摘要、规范字节、IR raw / document identity、完整 P2、精确目标、语义与生成器身份。即使新旧断言等价，也不能复用旧 raw digest。名称映射在生产中应由编码器内部产生并重建校验，不能让调用方任意提供。

P4-A 后续接入须另行接受显式 profile 支持范围，并重建新查询的 symbols、derived 白名单及 layout，仍严格核对请求 / 响应 / model 来源绑定。被内联的定义从 derived 清单消失；模型出现未知旧名字必须拒绝。既有 unknown、模型完整性、Text literal 冲突、预算和非成功退出规则不放宽。

### 有界代入的精确研究选择

先从断言根计算规范 DAG 的引用次数（根计一次），按拓扑序处理项。字节数取 ASCII 渲染长度，表达式嵌套高度独立于 DAG 深度：

- 长度不超过 16 字节的小常量可直接代入。
- 单次使用的表达式只有在长度不超过 128 字节且高度不超过 8 时代入。
- 多次使用的表达式进一步限制为不超过 32 字节且高度不超过 8，并要求 `uses × expression_bytes < definition_line_bytes + uses × name_bytes`。右侧使用当前待分配的 `dN` 名称及完整定义行长度；相等时保留定义。
- 其他项保留零参数定义，其引用高度重置为 0。代入不新增任何自由名称。

引用次数来自 DAG，后续父项内联可能再次复制子文本，因此这个判定只是确定性的局部表示策略，**不声称任意图上的全局最优或逐步单调缩小**。表达式长度 / 高度及最终输出上限继续限制展开。生产规则必须固定这些参数并绑定规范，不能由调用方隐式调参而仍使用同一 profile。

## 资源与停止条件

研究预算与生产资源分开：研究程序需要读取原来的大 SMT，故有独立输入 / 输出 / 项 / 边 / 深度 / 整数字数及内联预算；允许测量大于 1 MiB 的研究结果，但明确报告其字节可行性拒绝。这不是增大生产 stdin。

研究默认输入上限 64 MiB、输出上限 16 MiB、原始 / 规范 DAG 项上限 1,000,000、原始边上限 5,000,000、原 DAG 深度上限 100,000、输入括号深度上限 16、单整数位数上限 4,096。它们是本地诊断的显式工作范围，不是 P3 / P4 的新生产预算；超出时不形成成功研究制品。Python origins 辅助文件另有字节上限，仍是本地导出数据，不宣称通用不可信模型解析能力。

内联受单项字节数和嵌套深度约束；高引用数和深依赖不会无限展开。共享与内联决策仍有处理成本，不能只按最终字节给生产编码器收费。正式实现必须在分配前累计原构造与规范化的项 / 边、值单元、工作栈和输出收费，并检查溢出；不能让共享后的缩小结果掩盖已经发生的工作。

本次不测量真实 solver 墙钟、峰值内存、proof 大小或模型打印行为。即使原容量新表示全部小于 1 MiB，也不表示现有 128 MiB / 6 s 执行资源足够。若后续 Rust 原型、模型校准或执行负载失败，保留对应阻断，不能自动增限。

## 进入生产实现前的验收范围

- 全部 72 条原 profile 记录逐项保持旧摘要、尺寸与绑定；新表示重复生成字节一致，不缩容量。
- 五类目标分别测量，完整 stdin 字节不超过 1,048,576；报告最大值与余量，而非只给平均压缩率。
- 既有四版独立语义材料覆盖重命名、Text / Enum / Fixed / Record / Option、严格求值、前置失败、无关故障、稀疏 / 零容量、lookup 和复合键。
- 原容量三候选包含满 100 槽位、乱序、重复键、inactive 无效载荷、Pre 失败和能区分两个 wrong 的手算世界；guard 与具体目标归因分别核对。
- 全部自由符号双射、sort、origin 和 Text 排序保持；缺项、错类型、重复 / 交换映射、旧名字混入和绑定篡改须在生产接入时拒绝。
- 原型恒等规则、负向 / 非法类型、深链、高元数、精确预算边界及超 1 MiB 结果均有单独检查；正式实现再按 Rust 资源模型验收。

本研究的完成条件是给出有实际尺寸与有限语义支持的选择及剩余门槛。接受新 profile、Rust 生产实现、P4-A 集成和真实工具执行是后续分别报告的交付，不由本稿状态自动接受。
