## 本批实现出口

[入口](../../scripts/prepare-cvc5-execution-review.py)重用既有 C2 `checked_plan`，重新核对原配方及真实原包 / 源码 / patch，再从已绑定内容库存生成完整布局。输出只是 JSON，不建立 SDK、源码副本或构建批次目录。[事件规则](../../scripts/cvc5-build-support/event_rules.py)消费 Python 中的显式事件值，不读取系统状态、不执行命令，也没有把声明转换成执行资格的入口。

布局和事件规则分工不同：前者验证预期文件关系，后者检查声明的顺序与预算。二者都不是宿主 / 工具接受记录。即使候选没有悬空链接或事件序列完整，也保持 `assembly_ready=false`、`execution_ready=false`、`build_ready=false`。主 cvc5 阶段仍通过原入口绑定真实依赖 manifest；本批事件组件只处理原配方的 32 个依赖步骤。

2026-10-27 接续：同一入口新增显式 `--recipe-version 0.2`，可核对[阶段声明与链接前留存材料](solver-local-cvc5-offline-v0.2.md)，成功仍返回 2 / readiness=false。原依赖事件规则保持不变；主编译的专用截获退出 78 由新的阶段规则处理，不套用下表依赖步骤 `finish` 必须为 0 的要求。真实控制面、冻结与最终链接尚未实现。下文逐次读取方案和三个选项保留原设计背景；当前限定候选以 ADR 0031 及新阶段规则为准。

## SDK 布局与安全组装

布局以 172 个包的 `data` 成员为唯一文件来源。每条记录保留路径、类型、大小、原权限、候选权限、原字节摘要或链接目标，以及所有拥有该路径的包名 / 版本；输入归档身份沿已绑定库存追溯。跨包完全相同的条目合并拥有者，任何类型、权限、字节或目标冲突拒绝。缺失父目录只作为明确的 `0755`、无包拥有者候选记录；本批实际库存没有这类目录。

路径复用已有源码路径检查；拒绝绝对成员路径、`.` / `..`、重复分隔符、控制字符、反斜杠、设备、FIFO 和未知类型。链接按未来隔离根解释，绝对链接绝不能在宿主根解析。循环、超过 40 层、向根外回退及含有“下降后再 `..`”的歧义目标均拒绝。链接目标中的尾随 `/` 与 `/.` 保留目录要求，不能把指向普通文件的 `file/` 或 `file/.` 规范化为成功；要求经过间接链接后仍有效，恰好 40 次展开后的终点仍须检查。依据见 Linux [path_resolution](https://man7.org/linux/man-pages/man7/path_resolution.7.html)；这里只检查虚拟布局，不声明实现完整内核路径解析或实际搜索权限。布局中的非目录不能成为其他成员的祖先，不能顺着包内链接写文件。硬链接必须最终指向实际普通文件且候选权限一致，经过符号链接也拒绝；悬空符号链接留作阻断项，不自动补文件。

未来组装只能在获得 C1 接受与独立授权后按以下顺序实现：

1. 绑定新批次的规范父目录与精确根身份，独占创建新根；所有写入通过根目录句柄约束，逐层拒绝链接和身份变化。不得仅用字符串前缀或一次 `resolve()` 检查后再按可变路径写入。
2. 重新核对原 `.deb` 字节，从 `data` 成员流式复制普通文件到独占目的文件，核对长度 / 摘要；不调用 apt、dpkg 或包内 maintainer scripts。重新审阅原归档元数据，拒绝未处理的稀疏文件、特殊类型、ACL、capability / xattr；现有库存只记录有限基础字段，不能声称已完整检查这些扩展属性。
3. 先目录、再普通文件、再硬链接、最后符号链接。硬链接目标必须为本批已核对文件，不能依赖 tar 顺序。父目录和目标始终通过同一根身份定位；关闭或写入错误保留原错误，不把部分文件当完整输入。
4. 候选显式移除所有 setuid / setgid 位，保留其余原权限，包括 sticky 位；符号链接权限仅作库存信息，不对其目标执行 chmod。所有文件映射至后续审阅的单一非 root UID / GID，不恢复归档中的任意所有者。该映射及权限差异必须在真实组装前接受，本轮没有实际修改权限。
5. 用不跟随链接的完整树回读核对每条路径、类型、模式、大小、摘要、链接原文及硬链接同 inode 关系；拒绝额外文件。记录实际 UID / GID、目录和文件计数，再冻结根为只读并独立读回挂载配置。再次核对后才能启动工具。

实际候选为 **14,719 路径 / 537,445,262 普通文件字节**，含 1,367 目录、12,525 普通文件、822 符号链接和 5 硬链接；字节数不是文件系统占用估算。仍有以下待决定事项，不能把本批布局当作完整可用 rootfs：

- `tar 1.34+dfsg-1.2` 的 `etc/rmt → /usr/sbin/rmt` 目标缺失。保留其来源和原文；不得借用宿主目标、运行 alternatives 或临时安装包。需要明确审阅其在本批工具使用中的处置，当前不自动豁免。
- `bin/su`、`sbin/unix_chkpwd`、`usr/bin/newgrp`、`usr/bin/wall`、`var/local` 共 5 处需要移除 setuid / setgid。即便构建命令没有直接使用它们，也不能静默保留特权位。
- `/proc`、只读 cgroup 观察、设备、工作树和 `/recipe` 是运行时挂载，不属于包布局。应单列精确挂载、读写能力及身份，不能混入 SDK 摘要或假装来自包。网络、宿主 socket、credentials、宿主 `/usr` 和共享缓存均不允许。

## 事件组件的精确范围

`DeclaredBuildTrace` 由已通过 C2 复核的配方、配方摘要和同一单调时钟域起点构造。每个事件必须有 `kind`、`at_ns` 及该种事件的闭合字段；拒绝未知字段、布尔值冒充整数、负值、溢出、时钟回退及超过 100,000 个事件。没有 JSONL 文件读取入口或不受限事件缓存；日志每块最多 1 MiB，只保留增量摘要与计数。

| 事件 | 检查与结果 |
| --- | --- |
| `start` | 严格匹配下一个配方步骤 ID；`step_sha256` 是实际命令 / 变换对象按规则函数规范化后的摘要，绑定 argv、cwd、环境覆盖和日志路径。选择步骤只能匹配两个已列分支之一；匹配不代表检测结果支持该分支 |
| `review` | 只能消费当前位置的 review-gate，保留外部证据摘要；记录为 `unverified-review-declaration`。真实适配器须另行验证审阅内容及身份，本组件不审批 |
| `log` / `close-log` | 分开统计 stdout、stderr 及有 CMake trace 的步骤；逐流与整批额度绑定原配方。关闭后写入、重复关闭、额外流、过大块、超额都失败 |
| `sample` | 检查声明的 memory / swap peak、磁盘使用、OOM kill、pids 拒绝、事件 / 库存字节；高水位 / 累计计数不得回退，数据使用量至少包含已记录日志与证据大小 |
| `finish` | 退出码须为整数 0，所有要求的流已关闭，最后日志之后有资源样本；保留外部 capture 摘要，不能单凭它认证真实输入读取、退出或产物 |
| `cancel` / `observer-loss` / `input-failure` | 保存具体原因，永久失败；要求整批终止并保留，没有自动重试或清理 |

所有步骤及审阅等待共用初始期限，原 5,400 秒中的最后 60 秒只留给终止 / 留证，达到 5,340 秒即拒绝继续。20 GiB 中预留 128 MiB 最终记录空间，日志和事件库存计入磁盘；此组件检查的是声明值，实际分配块、inode、删除后仍打开文件和并发峰值必须由独立限额与观察覆盖。最终样本不证明中间没有越额，`jobs=4` 也不等于 PID 数上限。

首个错误不可被后续成功事件覆盖，结果保留已完成步骤、审阅声明和当前部分流的字节数 / 摘要；超额块不继续累计，调用方必须另保留超额发生事实，不能把截断后的日志标为完整。`sequence_complete=true` 只表示有限声明序列满足这些规则，仍不产生执行资格、C3 完成、ELF 验收或形式证明。

## 真实适配器的输入、输出与失败边界

执行适配器将来必须把下面事实绑定到同一批次 / 配方摘要 / 精确隔离实例；本批没有制造这些记录：

- **启动前读回：** C1 接受、组装树、宿主架构、镜像 / 根、只读与可写挂载、有效身份、环境、网络、memory / swap / disk / pids / inode 限额。PID / inode 额度、观察间隔与时钟误差目前尚未核定，不填猜测值；这些是执行阻断项。
- **进程与时间：** 外层持有精确实例身份与独立 watchdog；内部驱动整个构建进程树并回收子进程。两侧分别记录本地时钟及观察区间，不相减跨系统的时间戳。步骤、检测和人工审阅均不续时；监督失联、超时、取消须由外层终止整树并确认无残留，不能只杀 make 的父进程。
- **输入读取：** 每条实际读取 / mmap / 执行对象、目录查找与生成输入都要绑定路径解析后的对象身份及来源。SDK 输入只来自冻结库存；生成文件须绑定生产步骤和摘要；内核伪文件需单列精确用途。未归属输入、观察丢失、队列溢出或日志不完整立即发失败并停批。当前没有选定或实现能覆盖此范围的观察后端；不得把 CMake trace、`.d` 或 link map 单独称作完整读取跟踪。
- **退出和留证：** receipt 记录精确实际 argv / cwd / 完整环境、开始 / 结束时间、退出 / 信号原因、流摘要、资源原始事实及所有中间材料。退出码 0 后还要完成输出 / ABI / 链接组成审阅。独立 checker 从真实 map、archive、响应文件、ELF 及原输入重核，不信任构建进程自报成功。
- **失败与清理：** 先停止精确实例、确认整树退出，再关闭流并追加终止结果。保留全部部分输出及失败，不自动删除宿主批次；终止未能确认时记录未知残留，不能宣称清理成功。以后仅在精确列举拥有的路径、类型、摘要并取得授权后清理，不产生宽泛递归删除命令。

此设计的下一出口是 C1 闭合后，对上述具体适配器与限额作执行前审阅；不把准备工作展开为无期限的工具链研究。SDK 组装、真实负向资格、依赖构建、主目标构建仍分别遵守[C1–C5 停止线](solver-cvc5-build-candidate-plan.md#批次占用授权与停止线)。

### 完整读取观察的可行性结论（ADR 0031 接受前）

**现有材料不能支持选定一个已经闭合的读取后端。这个缺口独立于 LibPoly，许可答复到达也不能直接开构建。** 只记录路径字符串和最终文件摘要不足以绑定实际读取的对象及当时内容。

| 路径 | 本次结论 | 具体缺口 / 停止条件 |
| --- | --- | --- |
| CMake trace、`.d`、link map | 继续作为对账材料 | 不覆盖所有生成工具、目录查找、失败查找和运行时输入，不能升级为完整观察 |
| fanotify 单独承担 | 排除为完整后端 | 官方手册明确不报告 mmap / msync / munmap 导致的访问 / 修改，队列也可能丢事件；挂载标记不能修复这些缺口。见 [fanotify](https://man7.org/linux/man-pages/man7/fanotify.7.html) |
| ptrace 全线程观察与受限输入对象模型 | 仅保留为下一次可行性审阅候选，不开始实现 | 需要同时覆盖 fork / vfork / clone / exec、FD 继承 / dup / close、相对 dirfd / cwd、脚本解释器和动态装载、目录与失败查找；还缺生成文件并发写入 / mmap 时的内容版本绑定，以及异步 I/O 等绕过路径的拒绝设计。单纯打开 syscall 日志不满足要求 |

ptrace 的线程级附着、不同派生事件与 `PTRACE_O_EXITKILL` 以[官方手册](https://man7.org/linux/man-pages/man2/ptrace.2.html)为依据；这些只是可用原语，不能证明当前宿主具备权限或已有完整观察器。事后重新打开同名路径可能得到被替换的对象，读取停止时的摘要也未必等于另一个线程实际读到的字节；只停止一个线程不消除这些竞态。

当时提出的后端审阅限于四项交付：全部线程 / 继承 FD 的覆盖；路径解析到稳定对象的绑定；生成输入的生产步骤与内容版本；观察丢失及未支持输入机制的停止。每项须提供正例、替换 / 并发负例、拒绝时点和代码职责估算。任一项仍需不受限追踪或新的通用安全框架，则报告不可实施并停止；另行提交成本 / 信任决策，不能自动换后端继续研究。当时没有可靠的人日或剩余维护额度估算；其后已选择 ADR 0031 的限定阶段路线，本地新候选不再沿此完整观察器方向实施。

### 额度、观察间隔与整树终止

原配方 `jobs=4`、8 GiB / swap 0、20 GiB、5,400 s 保持。**PID 上限、inode 上限、采样间隔仍未核定，不写入猜测值或假资格记录。** 已有路径数只能描述 SDK，不能推出构建临时文件和线程上界。

| 项目 | 可审阅的实现方向 | 缺失证据与拒绝条件 |
| --- | --- | --- |
| PID | 构建专用 cgroup v2 `pids.max`；计入 shell、compiler、assembler、检测程序及线程 | `jobs=4` 不是此上限；需要选定数值、启动前实际读回和 fork / clone 超额负例。已有 `pids_denied` 声明不是强制能力 |
| 磁盘 / inode | 精确专用文件系统或 project hard quota 同时限制分配块和 inode；运行写入与最终留证分离预留 | 未选定文件系统 / quota 后端，不能保证删除后仍打开的文件、并发写入、元数据与日志空间。仅扫描目录或 `du` 不合格；现有 128 MiB 留证预留也需要实际保留机制和 inode 余量，不能只在事件里减去该值 |
| 观察间隔 | 内核硬限负责容量强制；单调定时器与外层 watchdog 负责超时，采样用于发现异常和留证 | 先绑定同一主机的最大采样间隔 Δ、调度 / 通信余量 J、整树终止 K、留证 F，验证 `Δ + J + K + F ≤ 60 s`。跨系统时钟不能相减；失联也不能重置总期限。尚无这些上界的实测证据，不宣称 90 分钟可靠收束 |
| 整树终止 | Linux 外层持有精确非 threaded cgroup 目录身份，候选使用 `cgroup.kill`，随后确认 `cgroup.events: populated=0` 并回收受管子进程 | 内部构建不能迁移出树或改写 cgroup；杀 make 父进程、向进程组发信号或一次 `docker stop` 返回不能代替整树确认。Mac 端还须绑定容器完整 ID / Linux 实例，避免同名重建误杀 |
| 外层失效 | watchdog 位于被终止的构建子树之外，由独立控制通道管理，不允许构建工具修改其代码 / 状态 | 其身份、内存 / CPU 占用、与原构建预算的关系和保护方式尚待接受；不能悄悄增加无限额辅助进程。需覆盖内部监督退出、外层失联、daemon 不响应、取消和期限到达；无法确认时保留未知残留，不能标清理成功或启动下一批 |

cgroup 的任务计数和整树 kill 原语依据 [cgroup v2 文档](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)；实际目标内核、控制器、权限与清理时限仍须负向资格验证。后端与额度方案未闭合前，不生成看似可执行的容器命令、不先组装 SDK 试错，也不放宽 solver 原 128 MiB / 6 s 或两进程策略。

### 本批结束决定

组装差异已形成有限候选，布局检查缺陷已修正；ADR 0031 的来源范围决定与 v0.2 离线切片已完成。11 月 1 日[有限接线与资格方案](solver-local-cvc5-control-plane-plan.md)及 [G0 盘点](../records/2026-11-01-cvc5-g0-capability-review.md)已交接；**G0 为证据不足，实际后端未核定，恢复须先指定精确现有 Linux 管理入口与候选根，或另作新检查通道的范围决定；尚不能进入真实接线或 C3。** 取得适用的 LibPoly 依据后另作 C1 接受审阅；不新增模拟层、重复许可历史取证或扩展全工具链清单。现行顺位统一见[接下来的事项](../status/current.md#接下来的事项)。
