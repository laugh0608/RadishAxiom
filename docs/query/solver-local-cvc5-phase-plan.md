## 核定结论与依据

**有条件可行，尚未取得真实资格。** 推荐复用原依赖阶段，在最终 CLI 链接前通过目标级 launcher 截获命令并明确停止；全部构建后代退出后冻结输入，再由控制面单独启动同一链接命令。这样保留上游编译图与链接顺序，不需要逐对象重写编译命令。真实生成的命令、响应文件、隐式输入、冻结后的运行及存储占用仍未知；任一项不满足既定边界就停止，不以本次静态结论放行 C2。

## 最小阶段与冻结对象

SDK 组装及其接受是阶段之前的独立门禁。表中各阶段只描述未来执行关系；阶段切换不重置整批截止时间、磁盘或日志额度。

| 阶段 | 复用命令 / 输入 | 可写部分与出口 |
| --- | --- | --- |
| 依赖构建 | 原工具查询、Editline 选择、探针、GMP、CaDiCaL、LibPoly、SymFPU 及原 review-gate；固定 SDK / 源码 / 配方只读 | 在独占工作区运行原配置、编译与安装；保留原次序。全部后代退出后，完整盘点并冻结输出前缀、配置头、日志和规定留存材料；真实依赖 manifest 经 review 后才能进入主阶段 |
| 主配置与编译 | 只读依赖前缀、SDK 与输入清单；独立 cvc5 源码副本及显式 patch；原 Production 参数、配置 review、`cvc5-bin` 构建 | 主源码 / build、临时目录可写。最终链接 launcher 只捕获原命令并以专用非零状态退出，不能调用链接工具。收束后冻结整棵主源码 / build 和原响应文件、对象、archive、配置及必要生成材料；此时没有 CLI，也不是构建成功 |
| 最终链接 | 固定 SDK、依赖前缀和上一阶段冻结树；原 driver / argv / cwd / 环境 | 仅 CLI 输出、map / trace 和声明的链接临时区可写。直接执行捕获的原 driver 命令，不重进 Make；全部后代退出后收集原始观察、冻结 unstripped CLI 并独立对账 |
| strip 与检查 | 只读 unstripped CLI 与固定工具 | `strip -o` 写独立输出，再分别 readelf；保存两份 CLI 身份和差异，不覆盖 unstripped 输入。完成仅形成待审新候选，E0 仍单独决定 |

依赖阶段内不强行拆开每个 configure / make / install：这些命令可能回写同一 build tree，拆得更细会引入额外副本与兼容问题。沿原配方保留内部 review-gate，阶段来源覆盖整组输入 / 命令 / 输出；不声称每个对象的完整逐读取历史。后续若需要额外阶段，必须说明实际消费者与成本，不能自动扩展。

冻结采用“收束、盘点、发布只读根、再启动消费者”的候选机制。完整阶段输出可以留作只读证据，但下一阶段只挂载明确登记的输入根；旧 tmp / HOME / logs 不默认继承。确需继续使用的生成文件先纳入 manifest，不能从上一阶段遗留可写目录读取。下一阶段临时区从空目录开始。

`chmod`、只读 bind mount 或前后摘要单独均不足以证明稳定性。真实适配必须确认所有构建后代、FD / 映射写入口已收束；冻结根由受信任控制面独占保管，没有普通宿主进程可写别名、共享同步目录或可逃逸链接。候选是控制面管理的 Linux 私有卷内发布冻结根，再以只读视图挂给消费者；容器客户端与存储后端的实际能力仍须核定。无法排除可写别名就停止，不能用宿主共享目录换取便利。该方案继续承担 ADR 0031 的宿主 / 控制面信任。

## 最终链接切口与必须核实的限制

1. **只给 `cvc5-bin` 加目标属性。** 下一批拟在独立源码副本上新增精确 patch，设置其 `CXX_LINKER_LAUNCHER`；单独绑定 patch、工具字节和 before / after 树。不得设置全局 launcher 影响配置探针、依赖或其他目标，也不得把两个 CLI 源文件移到另一个对象库而改变编译属性。原“无 launcher”配置审阅只在新版本明确允许这一项；其余设置仍拒绝漂移。
2. **截获是工具观察，不是成功收据。** launcher 有界记录完整 argv、cwd 与必要环境，不启动 driver，不生成假 CLI，随后返回专用非零状态。Make / CMake 的真实失败码和 stderr 原样保留。控制面只有在恰好一次预期截获、没有其他首错、材料齐备且完整收束后，才可报告“链接待审”，不能将退出码改成构建成功。重复、缺失、伪造、先前编译失败、截断或超额都拒绝。构建进程打印的标记不能认证外围事实；须交叉核对冻结 `link.txt`、生成规则、配置和对象，并继续显式信任固定构建工具。
3. **原样重放 argv，保留必要重复。** 不从日志行用 shell 拼接命令，不把 `-l` 清单排序或去重，不换成手写 `ld` 命令。记录 shell 展开后 driver 的 argv，并保留原始生成命令与响应文件。下一批仅支持固定工具组合的实际所需语法；不做通用 Make / shell 解释器。尚未运行 configure，因此当前没有真实 `link.txt` 或完整链接命令可供接受。
4. **输出分离而不改 `-o`。** 原命令输出 `/work/build/cvc5/bin/cvc5`；候选在冻结 build 树上将 `bin` 挂为独立空可写目录，保持原绝对 / 相对路径与 cwd。原 `-Map,/work/evidence/cvc5.map,--cref,-t,-t` 也保留，该目录仅收工具产物，受保护 receipt 存于构建不可写的控制面。必须确认被覆盖的目录没有链接输入；若有则拒绝此布局并重评，不能隐藏输入。前一阶段全部证据留在冻结存储，新可写层不能覆盖它们。
5. **核对显式与隐式输入。** 对象、archive 有序成员及重名序号、响应文件、脚本全部在链接前固定。GCC specs、CRT、默认库和搜索根来自冻结 SDK / 前缀；以已有工具查询、map / 双 trace、原字节和 ELF 交叉核对，不能把未来实际闭包写成已知。绝对 / 相对路径、响应文件递归与符号链接都须解析到登记根；成员缺失、未知默认库或额外搜索根均拒绝。
6. **链接期间新增输入是待验风险。** 保持原 `ENABLE_IPO=OFF`，不启用 LTO。仍须实测 driver / collect2 / ld 是否生成并消费额外对象、脚本或响应文件；若它们成为未预先冻结的必要链接输入，当前方案不能通过，先报告并重新审阅等效不可变边界。链接 tmp 不是允许未知来源的豁免。阶段时间变化可能影响输出字节，本方案不承诺可复现构建或与原 CLI 相同摘要。

不选改写 `build.make` 或新造编译目标，以免维护生成器内部格式及属性复制。若固定版本的 launcher 行为不符，保留失败并重评，不自动切换路径。

合计可见范围约 7–14 人日，不能因此承诺真实候选必然完成。建议下一批以 **4 人日等效投入为重评点**；到点仍未闭合就报告已实现 / 失败 / 剩余，不追加下一轮模拟或自动建设通用框架。尚未建立可靠工时账，实施开始时应记录实际投入和估算变化。

在版本全部固定且没有新批次时，新增维护预计每月 1–2 小时复核变更触发与待办；任一 cvc5 / CMake / GCC / Binutils / runtime / 内核变更，离线重核另估 0.5–2 人日，真实资格成本另算。此处不安排自动轮询，也不保证这些投入已经可由唯一维护者承受。实施者负责固定范围交付，独立复核者负责原字节与拒绝审阅，项目所有者决定是否承担持续责任及精确 E0 接受。

新增可信职责限于阶段 / 身份判定、命令截获、冻结 / 启动控制面与来源复核；SDK 工具、OS 与 runtime 信任仍在。离线规则和 launcher 不能替代后两者。必须报告新增自有生产代码规模与职责，不把既有产品的 8,000 行、10 人日或每周 4 小时安排当成本方案余额。

存储成本尚未实测。优先使用同一受控存储中的只读发布而非每阶段完整复制；若平台只能复制，原数据、冻结副本、临时区与证据须全部计入原 20 GiB / 日志与留证额度，不能把快照或控制面数据藏到额度之外。字节 / inode / hash 开销与资格失败都可能否定估算；需要增限、改工具 / 功能面、扩公共格式、无法固定输入或必须引入通用安全框架时，结束本切片并提交重评。
