# 本地 cvc5：控制面、冻结与真实资格接线方案

日期：2026-11-01。状态：**方案审阅完成；随后 G0 有限盘点以证据不足结束，真实接线不放行**。用途：把[阶段计划](solver-local-cvc5-phase-plan.md)中剩余的控制面职责、实现位置、负向资格和结束决定收敛为一批可审阅工作。读者为实施者、验收者与项目所有者。本文不定义公共格式，不接受宿主 / 工具，不授权组装、探针、构建或 solver，也不改变 [ADR 0031](../adr/0031-local-cvc5-build-provenance-boundary.md)的信任边界。当前顺位只由[当前状态](../status/current.md)维护；方案事实见[前批记录](../records/2026-11-01-cvc5-control-plane-review.md)，有限能力结果见 [G0 接续](../records/2026-11-01-cvc5-g0-capability-review.md)。

后续按项目所有者要求完成[新 Linux 通道最小方案](solver-linux-management-channel-minimum-plan.md)：唯一候选为同一 daemon 的一次性非 root 只读诊断容器，已列固定镜像候选、权限、资源和精确清理；没有接受镜像、执行例外或创建环境，也没有解决独立终止 / 冻结。下一批先完成精确工具和有界采集 / 编排的离线审阅，再就具体诊断执行另行决定，不重跑 G0 盘点或直接部署常驻控制器。

精确镜像和权限的[后续离线核对](../records/2026-11-01-linux-channel-offline-review.md)已取得平台字节链、原始 rootfs 514 项相对树一致、16 包 / 10 配方版本 / 许可声明以及参考内核路径；没有接受镜像或本机可读性。新发现 BusyBox timeout 直接位于容器 PID 1 的内部强杀假设不能成立，最小方案已要求保留 PID 1 监督 / 回收角色、改用非 PID 1 采集子进程；未实现或运行，不提高冻结 / 独立终止资格。

## 结论与直接出口

已完成的 v0.2 是离线阶段 / 链接前材料检查。`phase_rules.check_declarations` 检查 `frozen`、`writers`、`writable_aliases` 和 `control_record_sha256` 等声明，但不观察 OS；`capture_link.py` 的输出位于构建可写目录，属于不可信工具观察。给这些结果外包一层容器命令，不能补出实际冻结或认证捕获。

本方案保留一个候选：现有 OrbStack Linux AArch64 宿主内的受信任控制面，独占保管私有存储，按既定四阶段发布只读输入，独立于 Docker daemon 的请求返回执行整树终止。**当前没有已选定且可验收的存储 / quota 后端，也没有该 Linux 控制面的执行入口。** 下表 G0 已完成一次有限盘点，但未取得 Linux 管理上下文与根 / quota / 独立终止读回，结果为证据不足。恢复须先指定现有管理入口和候选存储根；不重复同类盘点或先建设通用卷管理器、读取观察器、第二套模拟系统。

| G0 必需事实 | 取得方式与可审阅出口 | 否定 / 停止条件 |
| --- | --- | --- |
| 精确 Linux 宿主与管理通道 | 在另行授权的最小宿主检查中绑定内核 / boot、runtime、已有管理入口、实际 namespace 与 cgroup；只读报告和执行资格分开 | 只能经阻塞中的 daemon 发 kill，或必须新开宽权限宿主服务才能观察；先报告，不自动启动 / 安装 |
| 私有存储、块与 inode 硬限 | 只核对该宿主现有文件系统、挂载 / quota 能力和访问权限，确定唯一后端、实际根身份、硬限单位与留证预留办法 | 只有 named volume、目录扫描、容器可写层大小或事后摘要；需要新增文件系统 / 工具 / 系统配置则停止并另提精确影响 |
| 写别名与管理权限 | 明确哪些主体能取得存储写句柄、挂载卷或控制 daemon；列出排除普通进程写入的机制与真实负例 | 无法排除未受控写别名，或必须把普通同用户进程整体升级为 trusted；不以“名字随机”放行 |
| 资源 / 时间参数 | 给出 PID / inode / 留证 inode 数值、控制面分配及 Δ / J / K / F 上界的依据，再安排负向资格 | 没有数值或依据不启动工具；`jobs=4`、SDK 文件数和文档算式不能代替实际边界 |

G0 不组装 SDK，不执行 compiler / solver；若已有管理通道仍需启动短时检查程序，先精确说明程序、权限、输入、时限、留存和清理再取得授权。G0 的只读能力结果也不能代替下文真实负向矩阵。许可未闭合时，可只使用另经审阅的自有合成材料准备环境资格；本方案不授权运行它们或使用未接受 SDK。

G0 的最小报告只取同一个 Linux 管理上下文中的内核 / boot 身份、`/proc/self/mountinfo`、`/proc/filesystems`、cgroup 控制器 / 目录权限，以及候选存储根的文件系统身份、quota 启用 / 硬限读回和允许访问主体。不用 Docker inspect 的容器配置替代 Linux 读回，也不扫描用户目录或保留凭据 / 完整环境。缺失现有管理入口就直接报告，不为取得报告起新容器或服务。检查建议单次最多 10 分钟、单项最多 8 秒，超时保留失败，不自动重试；只读检查不留下后台进程或临时卷，筛选报告保留。仅这些事实足以判断是否值得进入接线设计；PID / inode 候选数值和时间分配仍须说明依据，后续资格失败就拒绝，不承诺用只读查询测出最坏运行上界。

实际 G0 结果：[本批观察](../records/cvc5-control-plane-2026-11-01/g0-observation.json)记录 `orbctl list --format json` 返回 `[]`，Docker 报告总容器数 / 运行数均为 0，已检查的 CLI 帮助没有宿主 shell 入口；未执行默认 `orb`、debug 或创建环境。macOS 原生文件视图存在，官方[文件视图文档](https://docs.orbstack.dev/features/native-files)说明其可读写容器 / 卷；[设置文档](https://docs.orbstack.dev/settings#hide-orbstack-volume)说明 `mount_hide_shared` 只隐藏 Finder 入口。上层目录 `os.access` 结果不构成子文件或普通宿主进程防写证据。此处不宣称平台绝无其他管理通道或任意存储都不可行；只是现有材料不足以放行本候选。

## 宿主基线与权限边界

11 月 1 日只读 `docker context show` / `docker info` 的筛选报告见[原字段留存](../records/cvc5-control-plane-2026-11-01/host-observation.json)。context 为 `orbstack`，daemon ID 为 `ad69e9f6-8215-4c61-96df-1178e1368456`，server `29.8.2`，架构 `aarch64`，内核 `7.2.12-orbstack-00394-gbecdd6130068`，cgroup v2 / cgroupfs；存储驱动为 `overlayfs`，driver type 为 `io.containerd.snapshotter.v1`。它们是 daemon 报告，不是隔离实例读回。内核不同于 10 月 17 日的 `7.2.9-orbstack-00391-g2b298d05fbd4`，旧观察不能认证新实例。镜像、底层文件系统、私有卷、UID 映射和控制通道仍未选定 / 验收。

Docker [卷文档](https://docs.docker.com/engine/storage/volumes/)允许同一卷同时挂入多个容器，并说明挂载会遮盖原目录；因此私有卷名与某一只读视图都不足以建立全局不可写性。[daemon 安全文档](https://docs.docker.com/engine/security/)要求控制 daemon 的主体可信。由此，本方案不能宣称抵御能任意调用该 daemon API 的恶意主体；若目标要求抵御普通同用户进程取得这种权限，G0 必须证实访问隔离，否则停止，不扩大 ADR 0031 的 trusted 集合。

| 主体 | 可持有的能力 | 必须阻断的通道 |
| --- | --- | --- |
| Mac 端客户端 | 绑定 daemon / 完整容器 ID、请求本批阶段、接收有界结果；不持有唯一终止责任 | 名称匹配后操作新同名实例、连接断开后无限续跑、跨系统时间戳直接相减 |
| Linux 控制面 / watchdog | 受审阅身份独占输入 / 发布根 / 外围记录；持有精确 cgroup 目录与终止能力；监督和定时职责留在构建子树外 | 把管理 socket、可写 cgroup、宿主存储句柄、控制状态或自身写权限交给工具；接受任意 shell / 路径请求 |
| 阶段驱动与构建进程 | 已接受映射后的非 root `65532:65532` 候选，空附加组、空 capabilities、no-new-privileges；只得本阶段登记输入与写区 | host PID / mount namespace、网络、daemon socket、credentials、共享缓存、未列 FD、迁移 cgroup、修改监督器或记录 |
| 独立来源复核 | 消费已留存的原字节、阶段和链接记录；重算身份并检查关系 | 仅采信 `success`、复用生产判定函数生成唯一期望、把来源复核称作程序语义独立 checker |

控制面是 ADR 0031 已声明的可信职责，但具体代码、权限和工具仍须接受。其 Linux 运行时拟沿固定 SDK 的 Python `3.11` / 标准库核对，不能继承本机 Python 或未审宿主解释器；若实际管理能力要求额外 binary、FFI 或依赖，G0 先报告精确范围，不自动补入。内核 / runtime / 管理员仍属现有信任，方案不声称防御其恶意伪造。

## 阶段切换与冻结对象

阶段顺序、根路径、原 flags、环境和库重复沿[已核定计划](solver-local-cvc5-phase-plan.md#最小阶段与冻结对象)，不改 `phase_rules.STAGES` 或旧冻结配方。下面是未来控制面的执行顺序，不是新的离线成功状态：

1. **入场与装载。** 先核对 C1、组装差异、精确规则 / 配方 / 原输入和本批资格。控制面独占新建存储根，并在任何工具启动前读回映射、挂载、FD、cgroup 与硬限；不从旧批次恢复缓存。SDK 与 `/recipe` 只读，运行时 `/proc`、设备和允许的环境输入单列。组装仍按原归档扩展属性、路径 / 链接及全树回读要求另行验收。
2. **阶段运行。** 每次仅开放该阶段明确写区；依赖、主编译、最终链接及后处理使用同一批期限与累计资源。主编译恰好一次截获后保留 launcher 78 与 Make / CMake 实际非零退出，截获文件不作外围收据。缺截获、重复截获、先前首错或假 CLI 均停批。
3. **收束与隔离写入口。** 停止提交新工作，取得受管退出结果；确认工作 cgroup `populated=0`，回收受管子进程并关闭流。控制面 / runtime 也必须清点自己保留的写 FD、映射及辅助写入者，撤销生产者的可写挂载 / 入口。冻结 cgroup 不是退出，也不能取消其他主体的 FD。无法确认所有写入者或 I/O 完成就不发布；没有全系统 FD 枚举器时，只能依靠已验收的独占所有权与禁止传递能力，不能自报零计数。
4. **采集与发布。** 在写入口撤销后按根目录句柄进行不跟随链接的全树盘点，记录路径 / 类型 / 模式 / 长度 / 摘要 / 链接 / 硬链接关系及阶段来源，拒绝额外特殊文件或未知变换。控制面以唯一对象身份发布只读根；目录 rename、chmod、`cgroup.freeze` 或某一只读 mount 单独均不是冻结机制。具体后端只有 G0 核定并通过替换 / 写 FD / 映射负例后才可使用。
5. **消费者读回。** 绑定发布根的文件系统 / 挂载 / 根对象身份和清单摘要，验证消费者实际挂载、读写能力、cwd、完整环境与 FD。下一阶段仅接收登记根，不继承生产者的 tmp / HOME / 日志写区。新阶段不得重新打开已发布根的写视图；以事后路径或相同摘要追认对象无效。
6. **最终链接与输出。** 从冻结材料取得原 driver argv，保序重放且不重进 Make。`/work/build/cvc5/bin`、`/work/evidence`、`/work/tmp` 是既有最终链接写区；挂载前按完整输入库存及路径解析检查是否遮盖任何必需输入，未知隐式输入也不能据“清单没有”排除。输入落在这些根内即停批，不改 `-o`、复制漏项或放宽材料规则。链接中新生成的必要输入必须先作稳定性重评，不能借 tmp 豁免。收束后保存 map / 双 trace 和 unstripped ELF，再以只读输入执行 strip 到独立输出。

全阶段输出可保留为证据，但必须分开“可访问集合”“工具使用观察”“实际链接组成”。现在的 `link_materials.check` 没有 map / trace 解析或完整隐式闭包发现能力；真实最终链接之前须完成隐式输入审阅，链接后仍须新增有限的实际组成对账，不能把现有 prelink 结果当成 A6 / E0 通过。

## 资源、记录与终止

原构建额度保持 4 jobs、8 GiB / swap 0、20 GiB、5,400 s；最后 60 s 用于终止 / 留证，128 MiB 属于 20 GiB 内的最终记录预留。它们仍是未测量候选，不是可用性承诺；solver 的 128 MiB / 6 s 与 pids 2 完全分开。

| 事项 | 有限方案与资格判据 |
| --- | --- |
| 内存与进程 | 同一批父 cgroup 的 hard limit 覆盖控制面 / watchdog、记录器及工作子树；控制职责位于工作子树外的受保护叶，按核定分配留出容量，工作负载不能耗尽监督预留。禁止 cgroup 迁移和新增未登记辅助进程；PID 按线程计数。**具体 PID 总数和监督分配未核定**，不能由 jobs 推出或临时扩容 |
| 块 / inode | 私有存储后端须强制限制全批的块与 inode，覆盖 SDK 组装、原数据副本、冻结树、临时区、日志、控制记录、已删除仍打开文件和实际存储开销。原包在既有留存区只读引用不重新计作新写入；新增副本必须计入。**inode 上限和后端未核定**，不能用 overlay 可写层选项控制卷或把 `du` 当强制限额 |
| 留证预留 | 构建主体不能使用的 128 MiB 与独立 inode 余量须由后端实际保留，所有控制记录开销仍计入全批。日志 / map 是工具可写观察，外围状态位于工具无法读写 / 挂载的控制根；只追加、独占创建并绑定批次和前序记录。摘要链只检测可见改动，不替代存储保护或独立信任源 |
| 时限与 lease | Linux 本地单调期限从批次入场固定；阶段、人工 review、重连都不续期，Mac 不发可无限展期的授权。Δ 为最大检测间隔，J 为调度 / 通信余量，K 为整树终止确认预算，F 为留证预算；须先选值并验证 `Δ + J + K + F ≤ 60 s`。这些上界现未核定，不能以算式声称已验证；失联及暂停 / 恢复也须进入资格 |
| 精确整树终止 | Linux watchdog 持有正确非 threaded 工作 cgroup 的目录身份，失败即 `cgroup.kill`，等待 `populated=0` 并取得受管回收结果；监督和收集继续在树外。控制通道不依赖卡住的 daemon 请求完成。只杀父 PID、容器名或一次 stop 返回不合格；无法确认清空时记录未知残留并封锁新阶段 / 新批 |
| 记录与清理 | 每个实例 / 阶段绑定规则、配方、输入 / 发布根、实际 argv / cwd / 环境 / FD、挂载 / UID / cgroup 读回、原始时间 / 流 / 资源事实、首错和终止观察。先留证再决定清理，默认不删除数据；后续只对列明且复核为本批拥有的实例和对象清理，保留失败与原包，不自动重试 |

内核 [cgroup v2 文档](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)定义 PID 计数及整树 kill；[quota 文档](https://www.kernel.org/doc/html/latest/filesystems/quota.html)区分块 / inode 的硬限和软限；Docker [run 文档](https://docs.docker.com/reference/cli/docker/container/run/#set-storage-driver-options-per-container---storage-opt)限定了可写层大小选项的驱动条件。这些接口说明不证明当前 OrbStack 后端具备权限、预留或有界终止能力；本批不套用 overlay2 / XFS 条件给 `overlayfs` snapshotter。

## A3 / A4 / A7 / A8 真实负向矩阵

以下均**未运行**，只是 [A1–A10](solver-local-cvc5-build-provenance-review.md#必需验收矩阵)的执行设计。每例先固定输入、预期和注入点，绑定精确宿主 / 实例 / 根 / 规则及原始结果；正例不替代负例。注入者分别作为普通构建进程、无控制权限的普通宿主进程或明确的故障注入者记录，不用 trusted 管理员能篡改作为“违反既有威胁模型”的结论。独立复核不导入生产判断函数。

| 对应项与注入 | 必须观察到的结果 / 拒绝时点 | 最小留存与清理条件 |
| --- | --- | --- |
| A3 正例：只挂登记 SDK / 输入与新写区 | 工具只访问批准根；读回实例 / 身份 / 挂载 / FD 一致后才放行首命令 | 读回原文和完整布局对照；结束后确认工作树清空进程而非删除文件 |
| A3 负例：已知存在的宿主哨兵、socket、网络端点、额外继承 FD、共享缓存 | 注入前确认目标存在 / 可用，构建主体实际访问失败；意外可达即停批 | 控制侧可达基线、构建侧拒绝 / FD 状态、失败与整树终止；禁止以 ENOENT 单独通过 |
| A4 正例：收束后发布，下一阶段读同一根 | 写入口撤销、全树盘点与消费者身份一致；不继承旧 tmp / HOME | cgroup 退出、写入口所有权、根身份 / 清单与挂载读回 |

没有可靠历史工时账，本批不回填“已耗费人日”。以下是一人日约 8 小时的人工实施 / 审阅估算，不是 Agent 墙钟时间，也不是新增授权额度：

| --- | --- |
