# field-origin 静态推导与 P4 接口审阅

日期：2026-10-08。状态：P3-F 已按 [ADR 0024](../adr/0024-core-field-origin-derivation.md)与[正式规则](core-field-origin-v0.1.md)完成本机组件验收，提交为 `e896341`，实际结果见[验收记录](../records/2026-10-08-p3f-validation.md)；P4-A / P4-B 仍为 Proposed。以下保留实施前审阅，接续 P3-E `47e3ff9`。

用途：供项目所有者选择下一实施范围，给实现者提供目标、输入输出、拒绝边界与验收矩阵。不定义新的公共 Evidence、证明支持、后端执行权限或完整非干扰算法。前批判断见[接续审阅](p3-structural-obligations-and-p4-review.md)，原义务以 [P2 v0.2](../evidence/ir-derived-obligations-v0.2.md)为准。

## 建议决定与实际缺口

建议下一批为 **P3-F：字段来源与保守标签的结构推导内部组件**。从原 IR 重建来源路径、标签判断和求值上下文，绑定原 P2 field-origin 目标，导出可独立核对的版本化记录。记录必须保留标签缺口，不能只输出“来源合法”。这是可解释、可复核的静态分析，不自动完成原 field-origin 的公共 prove support。

P4 的单目标尝试没有依赖全部 field-origin 目标完成的技术理由。本稿同时确定 P4 组件拆分；P3-F 后可直接接续纯协议 / 解码组件，再交付具体重放器，不继续按义务清单逐项增加 SMT。真实执行及完整 Evidence 集成另行验收。

本轮调用既有 `scripts/generate-p3-query-review.py` 的 `coverage()` 核对 26 份 IR / P2 原始摘要与清单，再沿 `output → node → table_type → record_type` 统计到 **161** 个目标：

| 输出节点种类 | input | filter | map | lookup_join | group |
| --- | --- | --- | --- | --- | --- |
| 顶层字段目标数 | 96 | 8 | 35 | 6 | 16 |

其中 public 155、sensitive 6；类型为 Int 27、Text 79、Enum 14、Bool 11、Fixed 14、Record 11、Option 5。三个文档含指向同一节点的不同输出别名：`all-numeric-positions`、`changed-pre`、`same-node-two-outputs`。这些是输入清单，不能记作已推导或已证明数；不能用现有 query 的 98 个形状内位置缩小本批覆盖。

## field-origin 的命题边界

原语义要求“来自允许的字段与表达式”，P2 将其绑定到实际 IR 投影及标签 / 依赖约束，没有额外任务白名单。本提案按以下口径细化内部分析：

1. **来源闭合**：输入接口、字段、字面值、闭合操作及绑定均由当前 IR 定义；每条引用能回到声明或合法表达式。常量允许没有输入字段祖先，不能误判为来源缺失。源数据的真实性仍是信任边界。
2. **静态标签判断**：按现有 P1 保守规则给出声明、表达式推导、复合类型摘要及下游传播标签；记录本地 `declared < inferred` 缺口，并保留通往相关上游判断的边。一个完整分析可包含缺口，不能把“记录有效”解释成“标签约束全部满足”。
3. **观察边界**：字段值、决定行集合 / 关联对象的控制依赖、严格求值上下文分别记录。控制上界不是泄漏见证；求值上下文不是 totality 证明。
4. **其他目标**：业务等式由 contract-guarantee 判断，运行故障由对应 numeric-range / totality 等目标处理，公开输出的值、行集合及故障非干扰由独立双世界目标处理。

没有缺口只支持本 profile 明确覆盖的静态判断，不补充 Pre 可满足性、不证明所有程序义务，更不能把 public 摘要解释成关系非干扰。存在缺口也不产生 `failed` 或合成世界：`if sensitive then 0 else 0` 和 `x - x` 都可能有保守缺口而没有值差异。尚未尝试求解不是 `unknown`。

该组件不改变 P1 接受集合，不给原 P2 definition / ID 增加隐藏白名单或更强拒绝条件。将记录接入 prove support 前，必须在新 Evidence 支持规则中逐项说明哪些判断足以支持原目标、剩余条件如何补齐；若届时改变命题，必须新版本，不能原地重新解释旧 ID。正式实施前以新 ADR / 规则冻结上述内部范围，本稿本身不替代接受。

## P3-F 的具体接口与记录

拟在现有 IR crate 内提供 `derive_field_origin` / `check_field_origin`，显式选择 `CoreFieldOriginV0_1`。输入沿用不可变 IR v0.2 CanonicalDocument、完整匹配 P2 ObligationSet、field-origin 目标 ID、GeneratorIdentity 和预算；旧 IR 须显式迁移，错误 kind / 接口 / 字段 / 绑定分别拒绝。整份 P1 类型、图及内容身份正确性仍是前提，不能将本局部分析宣传为完整独立 P1。

内部记录拟标识为 `axiom-core-field-origin-derivation/0.1`，与 effect 记录和 query 分开。以下为待冻结的内容契约，精确闭合成员、规则 ID 与字节在接受后的正式规则中定义：

| 内容 | 必须可核对的信息 |
| --- | --- |
| 绑定 | IR raw / 文档域、语义、完整 P2 raw、目标 ID、规则 profile、生成器身份 |
| 目标 | 原 output 接口名、顶层字段名、实际节点与字段类型；不同别名不得合并义务 |
| 步骤 DAG | 输入接口 / 字段与类型声明、表达式 anchor + 规范 path、节点字段 / 控制判断、闭合规则 ID 和有类型的前提边 |
| 标签判断 | declared、inferred、propagated 分开；propagated 按现有规则取声明、推导和适用复合类型摘要的上确界，不能覆盖原推导值 |
| 根与缺口 | 所选字段值根、所属节点行控制根、求值上下文根；本地判断及相关上游缺口可沿引用找到，不能只复制输出节点的 label_gaps |

前提边区分值、选择 / 行控制、求值上下文和声明依赖；选择判断既可影响值，也可影响行集合，不能只给一个无解释的 sensitive 位。图与复合类型共享引用，不枚举全部来源到目标的路径；消费者沿 DAG 查询来源。一步可以有多类前提，但不能把 evaluation 边偷偷算成值标签，或反过来用没有值依赖删掉严格求值上下文。

按规范图顺序与明确表达式子项序输出；path 从内容 anchor 的规范 definition 开始，复用字符串数组约定，不能保存 P1 原输入数组位置诊断作为身份。所选目标只引用其真实依赖闭包；完整文档身份仍绑定未引用节点和契约。无关分支 / 节点中的缺口不得冒充该字段的值来源；相关来源中的缺口不得被下游声明“洗掉”。

全部合法逐行构造及五种节点均支持，不随 query 的 join / group / 契约量化限制缩小范围。公式契约不是节点字段来源；它们仍由完整 IR 身份绑定，但本记录不为公式真假、Pre 故障或非干扰生成推导。根字段为复合类型时保留带形状的内部判断，仍只绑定一项顶层义务，不展开成新的叶义务。

## 推导规则必须保留的区别

本批以 [P1 节点流分析](../../crates/axiom-ir/src/nodes/flow.rs)、[表达式标签分析](../../crates/axiom-ir/src/expressions/labels.rs)及其[回归](../../crates/axiom-ir/src/nodes/flow_tests.rs)为现状依据；独立核验器必须从 IR 重建规则，不能把这些 API 的结果当期望。正式规则若与现状有差异，先定位规范还是实现过期，不能为凑一致放宽规则。

| 构造 | 值与标签 | 必须另外保留 |
| --- | --- | --- |
| input | 精确接口 / 字段与声明；复合值摘要含适用的嵌套标签 | 输入行存在性为 public 是当前语义假设，不保证现实来源 |
| literal / none / some / bound | 字面值无输入来源；Option 形状与 de Bruijn 环境明确；None 无实际载荷读取 | 类型声明标签与表达式读取分开；Some 绑定移位可复核 |
| field / record | 直接字段读取不混入无关兄弟字段的值；复合记录保留各字段形状；已汇总的保守值不伪称精确最小来源 | 构造记录再投影仍引用完整构造的求值上下文，未读兄弟可能故障 |
| if / match_option | 保守合并条件 / subject 与所有分支；与 P1 一样不借相同分支、常量或 Pre 抹除依赖 | 两分支都静态存在；这不宣称两分支都动态执行 |
| 算术 / 比较 / Bool | 显式操作数来源合并，不化简 `x-x`；and / or 严格求值 | 算术范围和可达性不在此判真 |
| filter | 值来源与字段标签透传；行控制合并来源控制与谓词标签 | 谓词求值路径；敏感筛选不必产生字段标签缺口 |
| map | 字段从实际表达式推导；声明与推导合并后传给下游；来源行控制单独传递 | 同行全部字段严格求值，不用目标字段成功代替整节点成功 |
| lookup_join | 左右绑定精确；匹配标签包含两侧行控制与 pairs 字段标签，进入投影推导及行控制 | 右侧选择依赖不能遗漏；恰好一次匹配仍由相应目标验证 |
| group | 组键来源明确；行控制合并来源控制与组键；count 依赖参与集合，sum 另含聚合字段 | 组键字段值与组存在性分开；保留上游改写，守恒另验 |

尤其不能用顶层 public 声明与“整个 Record 含 sensitive 子字段”的摘要直接比较，发明原 P1 没有的缺口。步骤须分别显示声明标签、类型摘要、逐构造推导与实际比较规则；嵌套字段读取可能保守继承父字段摘要，不能宣称精确关系依赖。若希望提高分析精度，另立改进目标，不夹带进本批。

资源至少限制 IR JSON、步骤、前提边、声明 / 字段描述、规范路径和输出字节，收费先于分配，累计溢出视为资源拒绝。避免复制所有祖先集合；图 / 类型 DAG 迭代处理，表达式深度受输入限制。资源随构造规模增长，不按容量展开槽位或所有世界；这不是 OS 硬内存保证。

独立 Python 核验器直接读取 IR / P2，以规则重建整份记录；不能导入 Rust 推导、读取 P1 label_gaps 当答案或照抄测试期望。有限向量和变异拒绝仍不是形式证明。实施时补充手算区分例，并分别统计“记录一致”“有 / 无静态缺口”“真实反例”，最后一类本批不产生。

## P4 最小接口：请求、响应、世界、重放

现有 `EncodedQuery` 已有 bytes、raw digest、完整 binding 和 QuerySymbol。模型解码需要同时绑定这些信息，单个 SMT 摘要不足以识别源接口 / 叶布局。建议拆为以下实质组件，不建立通用 runner 框架：

| 入口职责 | 输入与输出 | 拒绝边界 |
| --- | --- | --- |
| 请求规划 | 经重建核对的 query + 完整 IR / P2 / 目标 + 显式 adapter profile / 工具身份 / limits → 不可变请求描述 | 旧 adapter 未显式支持 query0.2、未知 profile、身份错配、缺少符号布局 |
| 响应解析 | 有界 stdout / stderr、退出信息、外层终止原因及请求绑定 → 严格状态帧和模型表示或协议诊断 | 重复 / 冲突状态、截断、超限、未知语法、非零退出；日志不能覆盖真实退出原因 |
| 世界解码 | 完整模型 + 原符号与 IR 类型布局 → 所有输入接口的确定性 world 候选 | 缺项 / 重复定义、类型错配、别名循环、非法 Enum / Bool / 整数、Text 类冲突；不补默认值 |
| 具体目标重放 | 原 IR / P2 目标 + world 候选 + 预算 → WF、Pre、精确目标违反的观察或拒绝原因 | WF / Pre 不成立、Pre 故障、其他目标失败冒充目标违反、预算不足 |

请求组件不接受任意命令字符串、外部路径或继承环境。原 query / binding / 符号表及请求描述分别记录 raw digest；符号表必须从相同编码入口重建，不能信任调用方提供的 origin。响应来源与真实进程的绑定由将来的执行层负责，纯解析器不能认证一段 stdout 确实来自 cvc5。

### 优先保留查询字节

旧 [cvc5 profile](../../contracts/execution-profiles-v0.1/fixtures/positive/cvc5-1.3.4-qf-uflia-v0.1.jcs)已经声明 `--produce-models`、`--dump-models`、`--check-models`、`--produce-proofs`、`--check-proofs`，stdin 为单份 query 后 EOF，stdout 为状态及相应模型帧。本仓没有实际模型输出材料；这是已登记的预期协议，不是本机运行证明。

因此 query 只有 check-sat 并不直接推出必须追加 get-model。建议先审阅以该选项路径消费完整模型的 query0.2 新 adapter 对应关系，保留 P3 四版字节。不因名称相近就放行旧 adapter；正式闭合的模型文法、输出顺序、工具 / profile 身份与真实样例仍须另行验收。若实际固定工具不能满足该路径，再单独提出命令会话方案，并为完整发送字节建立新身份；不能偷偷追加命令而复用原摘要。

### 解码与重放边界

模型语法应限定为精确工具输出的受支持子集。所有自由 QuerySymbol 都必须有可解释的定义；派生辅助符号若出现，也要按明确文法处理，不能把未知 model 成员全量忽略。只支持纯常量 / 有界可解析别名等已声明项；未支持项返回诊断，禁止求助宿主执行任意 SMT 文本。正式 parser 实施之前需固定各帧文法与 token / 深度 / 整数位数 / 定义数预算。

- 输入按原容量槽位解码 active 和叶；只将 active 行及 Some 的有效载荷物化为 world。inactive 行 / None 载荷仍须满足响应文法及符号完整性，但不能要求它们满足未激活的 IR 范围，也不能读取或暴露为实际输入。
- Int 与 Fixed 系数按数学十进制整数，Enum 按原成员序，Record / Option 按原深度优先布局。对完整活动输入重新检查范围、键唯一、容量和外键，再按语义键序外部化；重复键不能通过排序 / 去重修复。
- Text 使用模型等价类。含已知 literal 的类映射回精确 literal，两个不同 literal 落入同一类必须拒绝；新类按其引用的最小规范 QuerySymbol 顺序编号，分配彼此不同且不碰撞任意已知 literal 的合成字符串。Unicode 不规范化。该映射只保留本域精确相等语义，不能声称还原求解器中的“原字符串”。
- 具体重放器直接解释原 IR，不能调用 SMT 编码器再执行同一目标公式自证，也不能复用 SMT 模型中的输出值。复用 P1 类型对象可以，依赖须显式记录；本仓实现仍不等于跨仓独立 checker。
- 目标按 P3 已接受规则分别重放：numeric-range 的实际 Reach 与 operandsOK；totality 的目标节点故障；key-cardinality / row-coverage 的 Ready 与容量前观察；contract-guarantee 的 ProgramOK 和公式 ok / value。每种目标都要有“其他目标失败而本目标成立”的拒绝例，不能使用一个全局失败位。

`SatCandidate`、`UnsatResponse`、解析 / 解码 / 重放诊断均为内部观察，不能直接填 Evidence 五态。真实 `sat` 也必须重放 WF、Pre 与目标；`unsat` 仍需按 assurance policy 处理 backend-attestation 或 certificate，空 certificate 支持集合不因 parser 完成而扩大。外层 timeout、内存终止、crash、solver unknown 和协议错误分别保留；未执行不形成 attempt。

## 实施顺位与接受范围
