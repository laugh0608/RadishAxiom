## 两处差异的源码依据

以下行号均针对精确 **GnuPG 2.4.7 上游原包**，不是补丁后重排的行号。原包、Debian 补丁和完整选定文本均可从本批留存库恢复。

| `g10/keylist.c` | `5c3f8731e1c8007ea652e919c1bb77a47bb9eea9a7c00f80f75ced07e92432f6` | 自认证列举与有效到期输出 |

### 到期字段：包内声明与工具有效值不同

`getkey.c:3549–3556` 先合并主钥，再合并子钥；`3560–3587` 在主钥已撤销、已到期或无效时传播相应状态。其中 `3579–3583` 在主钥已到期时：保留更早的子钥到期；若子钥无到期或晚于主钥，则把工具内存中的子钥 `expiredate` 限制到主钥值。`keylist.c:1998–2003` 输出该内存字段，`DETAILS:148–150` 定义它为 colon 第 7 列。

因此，对本批已固定且主钥已到期的材料，列出的子钥有效到期应是 `1736961163`，与原绑定包声明 `1736961679` 同时保留；两者相差 516 秒。不能改写原 OpenPGP 包，也不能把这段带条件的实现泛化为所有工具、所有时间点均执行无条件 `min`。

### 状态通知：按检查调用发出，不保证每把钥匙仅一条

`DETAILS:755–769` 说明 `KEY_CONSIDERED` 绑定主钥完整指纹及 flags，而 `KEYEXPIRED` 只有到期时间，甚至可能针对未用于当前签名的子钥；文档要求判断消息 signer 到期时看 `EXPKEYSIG`。它没有为 `--check-sigs` 规定全局一次通知或固定条数。

`sig-check.c:414–427` 在每次签名元数据检查发现钥匙到期时直接输出 `KEYEXPIRED`，没有按指纹去重。`1173` 的缓存路径也会调用该检查，但本项目固定命令含 `--no-sig-cache`，本批归因使用 `1217–1227` 的子钥绑定和 `1258–1265` 的 UID 路径，不能将缓存分支写成本次动态轨迹。

`getkey.c:3021、3178–3182、3370、3549–3556` 连接 UID 自认证、主钥到期赋值及子钥绑定检查；`4049–4053` 在合并后报告 `KEY_CONSIDERED`。`keylist.c:857、891–892、2075–2088` 再按具体签名进行检查并列出 `sig:!`。这条静态路径支持“查钥合并时一条到期通知，随后列举两份自认证时各一条”的解释，与历史四行输出一致。

这个调用归因是**基于源码的静态推导**，没有新运行的逐函数 trace，也不是 GnuPG 协议保证总是恰好三条。修订候选只为该固定五包材料和既有命令接受历史已观察到的精确四行序列；新序列依然拒绝，不能依据重复通知数量推导独立密码学结论。

## v3 离线联合判定候选

[候选入口](inspect-gmp-certification-v3.py)标识为 `gmp-certification-expiry-v3-offline-candidate`。它只做离线判定，没有容器执行或真实验签入口，未接入旧 v1 / v2 编排器。

- 自认证 status 必须逐字节等于：一条固定主钥时间的 `KEYEXPIRED`、一条固定完整主钥及 flags 0 的 `KEY_CONSIDERED`、再两条相同的 `KEYEXPIRED`。最多 256 bytes，不去重，不忽略未知行，不接受其他顺序或更多重复。
- 与原始及导出五包材料、两份 SHA-256 自认证、UID / 主子钥指纹、算法、class、创建时间、`sig:!` 和已到期状态联合检查。原始包声明继续由旧库存判定器核对；独立输出 `packet_declared_expiry` 与 `listed_effective_expiry`。
- 仅在观测时间为真实记录中的整数且晚于全部固定到期值时使用主钥已到期分支。stdout / stderr / status 各至多 1 MiB，colon 至多 4,096 行、单行 8,192 bytes；未知记录、退出失败、超限和采集失败仍拒绝。
- 历史方法已绑定摘要，故新文件保留必要的版本化 colon 判定，不修改旧文件，也不通过篡改全局 `EXPIRES` 或规范化输入复用旧判定。历史失败仍按原方法重放。
