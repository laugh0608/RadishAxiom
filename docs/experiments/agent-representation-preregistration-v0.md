# Agent 表示与验证反馈对比实验预注册 v0.1

状态：Accepted

更新日期：2026-08-20

用途：在查看任何正式试验输出前，冻结首轮 Agent 对比实验的研究问题、变量、模型条件、样本量、指标、阈值、停止条件和防泄漏边界。

读者：实验执行者、基准维护者、表示与工具链设计者，以及审阅 RadishAxiom Agent 价值主张的协作者。

不包含：实验成绩、模型调用、表面语法决策、编译器或验证器实现、实现语言、验证后端、宿主运行时选择，以及对通用软件工程的泛化结论。

## 核心结论

首轮实验是一个小型、配对、确认性协议，不是模型排行榜：

- 比较三种语义等价的候选表示：领域熟悉的 SQL、普通 JSON plan、研究用途的 Axiom projection；
- 使用两个固定 Agent 条件、四个 AX-B01 至 AX-B04 任务和三个重复，共 72 个 trial bundle；
- 每个 bundle 产生零样例首答和少样例首答；少样例首答失败时，从同一原始回答分叉到等价自由文本反馈和结构化 Evidence 反馈，各最多修正两轮；
- 最多允许 432 次模型调用，不因中途结果好坏提前停止；
- 正式结果只能由隐藏夹具、语义义务和独立 Evidence 检查共同判定，不能由字符串相似、公开示例或人工观感替代；
- 本协议只检验“表示和反馈是否对 Agent 有实际帮助”，不会自动冻结任何产品语法或工具链。

机器可读参数见 [`experiments/agent-representation-v0.1/registration.json`](../../experiments/agent-representation-v0.1/registration.json)。该文件的原始摘要由相邻 `registration.sha256` 固定。

## 两阶段封存

预注册分两层，二者都必须在首个正式 benchmark 调用前进入版本控制：

1. **协议注册**：本文和 `registration.json` 冻结问题、设计、模型别名、样本量、指标、阈值与停止规则。本批只完成这一层。
2. **执行锁**：未来的 `execution-lock.json` 固定实际模型 revision、公共 system prompt、三份表示卡、两份少样例演示、任务卡、适配器、评分器、独立检查器及其原始摘要。

允许在执行锁前用与四个基准不重叠的 smoke task 调通装配，但不得请求 AX-B01 至 AX-B04 的任何回答。执行锁完成后，若改动提示、表示卡、演示、适配器、评分规则、模型 revision 或预算，必须提升实验版本；不能在原登记下悄悄重跑。

## 研究问题与假设

### 确认性问题

- **Q1 / H1：表示价值。** 在相同任务信息和少样例条件下，Axiom projection 是否比 SQL 与普通 JSON plan 提高严格首答成功率？
- **Q2 / H4：反馈价值。** 对同一个失败首答，结构化 Evidence 反馈是否比携带相同事实的自由文本反馈提高两轮内修复率？

### 次要与探索性问题

- 零样例与少样例的差异，用于衡量新表示的上下文学习成本；
- 解析、类型 / 效果、契约、隐藏输出和 Evidence 各层错误分布；
- 修正轮数、可见 token、墙钟时间、验证时间和反例质量；
- 两个模型条件下效应方向是否一致；
- 显式中间状态、字段来源和 trust / `unknown` 是否减少隐式状态错误。

H3 双投影、H5 独立证据可信度和 H6 跨领域迁移不属于本轮确认性结论。即使本轮成功，也不能声称这些假设已经成立。

## 实验单位与配对

一个 trial bundle 由以下键唯一标识：

```text
model_condition × representation × benchmark_id × replicate
```

固定因子为 2 个模型、3 种表示、4 个任务和 3 个重复，因此共有 `2 × 3 × 4 × 3 = 72` 个 bundle。`replicate` 只表示独立请求编号，不暗示模型支持可控随机种子。

同一 bundle 内：

1. 零样例会话独立产生一次首答；
2. 少样例会话独立产生一次首答；
3. 若少样例首答未达到严格成功，保存完全相同的原始回答与评分事实；
4. 从该状态分别创建自由文本和 Evidence 两个反馈分支，每支最多两次修正；
5. 两支反馈必须携带同一失败义务、字段、键、反例和值，只改变编码结构和协议措辞。

不得让一个反馈分支看到另一个分支的回答，也不得把零样例回答带入少样例会话。

## 三种表示条件

所有条件表达同一输入模式、输出模式、前置条件、保证、效果和字段标签。任务信息差异必须由执行锁中的语义对照表审计，不能让 Axiom 条件获得额外业务约束。

### R-SQL：`sql-select-v0.1`

- 角色：领域熟悉基线；
- 产物：一个只读、单 statement 的 SQLite-compatible `SELECT`；
- 允许：子查询、`CASE`、等值连接、筛选、投影、`GROUP BY`、`COUNT`、整数 `SUM`；
- 禁止：DDL、DML、UDF、扩展、外部表、窗口、顺序依赖、任意副作用和多 statement；
- 契约与字段标签由相邻任务卡表达，不把 SQL 测试通过误称为证明。

这里的方言只服务实验基线，不选择产品运行时或 SQL 后端。

### R-JSON：`neutral-plan-json-v0.1`

- 角色：普通结构化 schema / DSL 基线；
- 产物：研究专用 JSON DAG；
- 允许的操作与首域一致：`input`、`filter`、`map`、`lookup_join`、`group`；
- 使用可读 symbolic name、显式字段表达式和单一输出；
- 不包含内容 ID、证明状态、trust、契约 AST 或 Axiom 专有命名；
- object member 顺序不计分，未知字段和未知操作拒绝。

### R-AXIOM：`axiom-projection-v0.1`

- 角色：候选 Axiom 人类 / Agent 投影；
- 产物：研究专用、可编辑的 Axiom IR v0.1 symbolic projection；
- 使用与 IR 一致的类型、节点、contract 与 effect 概念，每个语义构造只有一种登记写法；
- Agent 不生成内容摘要；适配器解析后规范化、计算 ID 并产生正式 Axiom IR；
- `proved`、`checked`、`unknown`、`failed`、`trusted` 只能来自评分与 Evidence 阶段，候选不得自报成功。

该 projection 明确不是 `.rax` 表面语法，也不是新的语义真相源。实验结果只能支持继续、修改或放弃这一研究投影，不能直接把它升级为产品语法。

## 提示与反馈条件

### P0：零样例

提供共同 system prompt、当前表示卡、任务卡和输出规则；不提供完成过的转换示例。“零样例”不表示无规范，新的表示仍必须获得完整参考卡。

### P1：少样例

在 P0 基础上增加两份与 AX-B01 至 AX-B04 不重叠的合成演示。两份演示必须共同覆盖五个核心操作、受界算术、键、聚合、字段来源和非干扰，并在三种表示间语义等价。演示不能复用正式任务的字段名、常量、键或行。

### F-TEXT：自由文本反馈

使用固定模板陈述失败层、失败义务、相关键 / 字段、期望与实际值，以及同一缩减反例。不得加入修复代码、目标表示片段或未在 Evidence 分支出现的提示。

### F-EVIDENCE：结构化反馈

使用 Axiom Evidence v0.1 的最小反馈投影表达与 F-TEXT 完全相同的事实，包括义务 ID / 类别、状态、反例、追踪路径、trust 和 uncovered。它不是完整生产 Evidence，也不能伪造 `proved`。

两个反馈分支均允许最多两次修正。模型每轮必须返回完整候选，不能只返回 diff。首轮已经严格成功的候选不进入反馈分支，避免用无意义继续对话稀释修复率。

## 模型与执行条件

首轮固定两个 Codex Agent 条件：

| 条件 | 模型别名 | reasoning effort | 用途 |
| --- | --- | --- | --- |
| M-SOL | `gpt-5.6-sol` | `medium` | frontier agentic coding 条件 |
| M-LUNA | `gpt-5.6-luna` | `medium` | fast / affordable 条件 |

共同执行边界：

- 每次调用最多 16,384 个可见输入 token、4,096 个可见输出 token；
- 不提供仓库、网络、shell、文件、浏览器、记忆或其他工具；
- 不继承此前对话；除固定 system prompt 与当前请求外没有隐藏任务上下文；
- service tier 固定为 `priority`；不设置模型不支持的 temperature 或 seed；
- 返回值必须只有完整候选，额外自然语言、Markdown fence 或多个候选均按登记解析规则处理，不人工清洗；
- 每次保存平台返回的精确 model / revision、usage、finish reason、request ID 和时间；
- 执行锁前用无任务内容的能力探针取得精确 revision；同一别名若在正式运行中出现两个 revision，立即停止整轮实验。

两个条件只是本轮复现实验的样本，不代表产品模型选择，也不足以推出跨提供商结论。任一别名不可用时不得静默替换；必须登记新版本。

## 任务信息、隐藏材料与防泄漏

每个任务卡可以包含：

- benchmark ID、输入 / 输出 schema、键、范围、字段标签和纯效果边界；
- 完整自然语言前置条件与保证；
- ADR 0002 的公开基础输入和黄金输出；
- 与当前表示有关的输出协议。

以下内容不得进入任何模型上下文：

- `candidates/` 下的正确或错误候选；
- boundary / invalid fixture 及其黄金输出；
- `expected/` 断言、真实评分、隐藏义务结果或另一试验回答；
- 仓库路径、Git 历史、摘要到内容的反向索引或能够检索上述内容的工具。

任务卡、表示卡、演示和 system prompt 必须在执行锁中保存原始字节与 SHA-256。装配后的每个实际请求也保存原始摘要。发现任一泄漏时，整轮结果作废；不能只删除“看起来受影响”的 trial。

## 评分层级

每次回答分别记录以下结果，不能压缩为单一解析成功：

1. **Envelope**：响应是否满足单候选输出协议；
2. **Parse / adapter**：对应表示能否被严格解析并确定性转换到 Axiom IR；
3. **IR structure**：规范化、类型、引用、键、字段、效果和版本是否合法；
4. **Verification**：全部必需核心义务是否 `proved`，且没有 `failed`、`unknown` 或用 `trusted` 绕过；
5. **Hidden execution**：base、boundary 和有效隐藏变体的规范输出是否与黄金结果一致；invalid 输入是否被输入符合层拒绝；
6. **Evidence**：Evidence 摘要链、义务集合、状态、反例、trust / uncovered 和 conclusion 是否被独立入口接受；
7. **Counterexample quality**：失败反馈是否可重放、指向真实失败约束、包含必要键 / 字段并准确声明最小性。

`strict_success` 只有在第 1 至 6 层全部通过时才为 true。公开示例相等、动态测试通过、解析成功或生产工具自报证明均不足以计为严格成功。

反例质量使用固定四级：

- `0`：缺失或不可重放；
- `1`：可重放但没有定位真实失败，或包含明显无关行 / 字段；
- `2`：定位真实失败并包含必要键 / 字段；
- `3`：在 `2` 基础上具有诚实的缩减 / 最小性标签和完整追踪路径。

可自动判定的部分由独立检查器完成；仍需人工判断的路径相关性由两名不知道模型与表示标签的审阅者独立评分，分歧在揭盲前裁决。

## 主指标与确认阈值

### H1：Axiom 表示价值

主指标是 P1 少样例首答的 `strict_success`。每种表示池化 24 个首答（2 模型 × 4 任务 × 3 重复），同时保留模型和任务分层结果。

H1 只有同时满足以下条件才记为 `supported`：

1. R-AXIOM 相对 R-SQL 和 R-JSON 的严格成功率分别至少提高 12.5 个百分点，即每个比较至少净增加 3 / 24 个成功；
2. 对两个模型分别计算的差值相对两条基线均不为负；
3. 没有任一 benchmark 在两个模型合计的 6 个 trial 中，相对两条基线都少 2 个或更多成功；
4. R-AXIOM 的中位可见总 token 不超过表现最佳基线的 2 倍。

未达到全部条件记为 `not_supported`；若核心评分器产生 `unknown`、有效 trial 不完整或发生停止条件，则记为 `inconclusive`，不能把两者合并。

### H4：结构化反馈价值

主指标是在少样例首答失败后两轮内达到 `strict_success` 的比例。F-TEXT 与 F-EVIDENCE 从相同首答分叉，采用配对比较。

H4 只有同时满足以下条件才记为 `supported`：

1. 至少存在 12 个可进入两种反馈分支的失败首答；不足时为 `inconclusive`；
2. F-EVIDENCE 的两轮修复率比 F-TEXT 至少高 16.7 个百分点；
3. 两个模型上的修复率差值均不为负；
4. F-EVIDENCE 的中位修正轮数不高于 F-TEXT；
5. F-EVIDENCE 的反例质量中位数不低于 `2`，且不可重放反馈比例不高于 F-TEXT。

样本分母、原始计数和每个配对必须与百分比同时报告。可计算配对 bootstrap 区间和精确检验作为描述性统计，但不以任意 `p` 值替代上述预注册阈值。

### 决策规则

- H1 supported：允许继续细化 Axiom projection，但仍需单独决策表面语法；
- H4 supported 且 H1 未 supported：保留 Evidence 反馈研究，重新设计表示后再登记实验；
- 两者均 not_supported：停止用本轮表示宣称 Agent 优势，先分析失败类型并提出可反驳的新版本；
- 任一 inconclusive：只能补齐装置或登记新实验，不能从不完整结果得出正向结论。

## 调度、预算与重试

- 调度使用固定字符串 `radishaxiom-agent-representation-v0.1` 作为 SHA-256 派生种子，对 72 个 bundle 做确定性乱序；
- 模型条件分块交错运行，避免所有同类表示集中在同一时间窗口；
- 每个 bundle 最多 6 次调用：P0 一次、P1 一次、F-TEXT 两次、F-EVIDENCE 两次；
- 正式上限为 72 个 bundle、432 次模型调用、7,077,888 个可见输入 token 和 1,769,472 个可见输出 token；
- 内容错误、格式错误、`unknown`、截断或 refusal 不重试；它们按真实结果计分；
- 只允许对未产生响应的传输错误按相同 request bytes 重试一次；再次失败记为 operational failure；
- 不做基于中间成功率的提前停止、加样、删样或提示修改。

延迟和价格按实际元数据报告，但不作为跨模型主结论，因为 service 状态和计费可能随时间变化。

## 停止、排除与失败关闭

出现以下任一情况立即停止整轮正式运行，保留原始记录并将结论标为 `inconclusive`：

- corpus、registration、execution lock、提示材料、适配器、评分器或 checker 摘要漂移；
- 模型 revision 在同一条件内变化，或平台没有返回可审计身份；
- 正确候选、隐藏 fixture、Expected Evidence 或其他 trial 回答发生泄漏；
- 生产评分器与独立检查器对义务集合、状态、反例或 conclusion 不一致；
- 任一模型条件的 operational failure 超过计划调用的 10%；
- 达到调用或 token 上限仍未完成计划；
- 出现凭据、隐私、安全或许可证问题。

主分析采用 intent-to-treat：malformed、refusal、截断和无法修正的回答均计为失败。只有平台确认没有生成响应的 transport failure 可以在单次重试后标为 operational failure；报告必须同时给出把它计为失败的主结果和排除后的敏感性结果。

不得因为任务“太难”、结果与预期相反、某表示看起来不公平或某模型表现异常而临时排除。装置 bug 必须在揭盲前由摘要或独立检查不一致证明；修复后提升版本并整轮重跑。

## 制品与可信边界

执行锁和未来试验记录至少保存：

- 协议、语料、语义、IR、Evidence、表示卡、演示、任务卡、提示模板和工具的版本与原始摘要；
- 确定性 schedule 和每次请求 / 响应原始字节摘要；
- 模型别名、精确 revision、reasoning effort、service tier、usage、finish reason、request ID 和时间；
- 每层评分、生成的 IR / Evidence 摘要、隐藏 fixture 结果、修复链和停止事件；
- 不可由自动检查决定的人工评分、审阅者匿名 ID 和揭盲前裁决。

仍然可信或未覆盖：

- 模型服务忠实返回其身份与 usage；
- system prompt 和平台级策略可能影响结果，必须记录但无法由项目证明；
- 表示适配器、验证后端和生产 Evidence 生成器在独立交叉检查前属于信任边界；
- 四个任务和两个同系列模型不足以支持通用语言、跨提供商或长期模型趋势结论；
- 合成数据不代表生产分布，基准规范也可能遗漏真实意图。

## 明确不包含与变更规则

本轮不比较表面语法美观、人类学习成本、IDE、包管理、宏、并发、外部副作用、生产性能或法规合规；不使用真实客户数据；不把 token 少直接解释为正确性高。

接受本协议不授权模型调用、购买额度、安装依赖、启动服务、提交实验结果或修改远程状态。实际执行必须另行确认，并先提交完整 execution lock。

在任何正式 benchmark 响应产生前，可以通过提升 registration 版本修正设计；首个响应产生后，任何语义材料、模型、样本量、指标、阈值、停止条件或分析规则变化都必须登记为新实验。失败结果同样保留，不能覆盖或只发布有利切片。
